# 三大专项新增条目可执行化深度研究（A12-A14 · D7-D8 · W7-W10）

**研究基准日：2026-11-21。** 本报告承接《调研报告_三大专项_20261120》，面向九头鸟后续技能库扩容，提供授权测试程序与技能设计依据；不是完整测试报告，也不代表对任何产品已实施测试。

## 摘要

本轮把九个新增条目拆成可在受控环境中执行、留证、复核的测试链。共同原则是先建立目标版本、身份、数据流和预期策略基线，再用测试租户、测试账号、合成对象及 Canary/mock 端点执行配对探针。只有观察到服务端实际决策、受保护资源访问或受控副作用，才可把影响定为确证；静态命中、扫描器提示、模型自述和单纯声明不一致通常只是候选或疑似。

建议首批落地 **A12、D7、W7（P0）**：其边界可用协议规范和测试账号清晰描述，失败判据较确定，且访问授权目标比宿主平台和生产云资源更可控。**A13、A14、D8、W8、W9（P1）**需要更强的运行追踪、业务策略解释或平台/云账户协作。**W10（P2）**适合先做证据模板和治理核验清单；法规、披露充分性和法律责任需由客户治理负责人判断，不应由技术扫描自动定性。

公开资料和工具的成熟度差异较大。MCP、Play Integrity、App Attest 有可操作的官方规范或样例；A2A、Agent 记忆污染和网关自适应测试仍需在本地 mock/harness 中补足目标适配器。微信、抖音、支付宝 IDE 是滚动发布产品；研究原型的稳定发行版或可复用代码若未能公开核实，本文明确标为未核实，不以论文结果代替目标产品证据。

### 共用执行契约

1. **授权与隔离**：工单须列明组织、应用/App ID、测试租户、账号、设备、接口、云项目/环境、允许流量及时间窗。跨小程序、宿主桥接、云管理面或第三方平台本身的边界测试，还需该边界所有者授权；应用所有者授权不自动覆盖平台基础设施。
2. **合成数据**：使用明确标记且无个人信息、凭证或业务价值的 Canary 对象、账号与操作。外送验证只指向本地 sink 或已授权的 mock 域名；不把合成标记发往公共服务验证。
3. **配对控制**：每个候选问题至少有阳性控制（按设计可成功的测试账号/对象/请求）、阴性控制（错误主体、错误租户、已撤销状态或不相关对象）和基线控制（未施加测试条件的同版本正常流程）。无法安全构造阳性控制时标注未完成，不推断漏洞成立。
4. **停止条件**：出现真实用户/非测试租户数据、真实支付/消息/写操作、越权 Canary、未授权出站流量、不可逆状态变化、服务不稳定、超出约定速率/预算或授权时间窗时，立即停止并保留最小必要证据；不沿着意外结果继续扩展。
5. **证据最小化**：每次保存目标版本/配置摘要、UTC 时间、测试主体伪名、请求/任务/trace ID、预期与观察结果、服务端决策和 mock sink 记录。令牌、授权码、session_key、个人信息和生产密钥不进报告；仅留可复核的哈希、脱敏片段或安全存储引用。
6. **确定性纪律**：脚本/grep/规则只能判定明确字段、调用、配置和事件是否存在。它们不能仅凭文本推断授权意图、隐私告知是否充分或业务规则是否合理；后者需要人工对照批准的策略和实际效果。

## A12 Agent 协议与委托信任边界

### 怎么测

1. **固定基线**：记录 MCP/A2A 规范版本、客户端与服务器构建、传输方式、授权服务器、resource/audience、工具清单、工具描述与 schema 哈希、每个工具的执行身份、允许出站目的地及授权策略。创建本地 MCP server、两个 mock 资源服务器和一个只记录、不外送的 sink。
2. **工具描述投毒与 shadowing/rug pull**：对自建 Canary 工具清单保存规范化快照；依次比较连接前、连接后、重连、批准升级后的工具名/描述/schema/服务器来源。用含无害标记的“可信基线描述”与“低信任变更描述”做差分；检查客户端是否显示来源/变更、要求重新批准或拒绝哈希不匹配。再确认模型/客户端实际选择的工具与批准清单一致。只分析描述与 mock 工具，不执行其声称的副作用。
3. **受众绑定与 confused deputy**：分别为 mock 资源 A、B 签发不同受众/范围的短时测试令牌。正向控制：A 令牌访问 A 上允许的 Canary 操作成功。负向控制：A 令牌请求 B，或通过 MCP 代理再访问 B，应由 B/代理拒绝且不得出现下游调用。核实 MCP 服务器没有把面向它的入站令牌原样转交给上游服务；对代理身份、用户授权、上游凭证分别记录主体映射与同意事件。规范还要求 resource 参数、受众校验及相应 OAuth 防护，测试应对照实际实现的规范版本。[R01][R02]
4. **出站数据流**：向 mock 工具结果放入唯一合成 Canary，观察 agent→MCP server→代理→sink 的 trace 和网络记录；只允许预先批准的本地目的地。检查目标列表、重定向、代理转发和错误重试是否改变目的地或身份。不给真实秘密做“诱饵”，不连未授权域名。
5. **A2A 身份/上下文传递**：在两个测试 Agent 间设置主体 A/B、不同 task/context ID 与权限。分别传递有效上下文、过期上下文、缺少授权主体的请求及来自 B 的上下文重放；观察接收方是否用可信认证信息重建主体、校验任务/范围并隔离会话。核对 Agent Card 声明的认证方案与实际验证一致。[R05]
6. **停止**：出现非 mock 工具被调用、意外真实上游请求、数据离开批准 sink 或服务端授予测试范围外权限，立即停止，不继续验证可访问资源范围。

### 用什么

- **MCP Inspector 2.14.0**：MCP 官方组织的交互式开发/调试客户端，可通过 npm 的 @modelcontextprotocol/inspector 固定版本运行，适用于本地或获批 MCP 服务；Node.js 要求随发行说明变化，安装前核对版本文档。它帮助查看协议交互，不是安全裁判。[R03]
- **Snyk Agent Scan 0.6.5.1**（前身 MCP-Scan）：开源 CLI，可通过 uvx 固定版本运行，适用于 MCP 工具/提示配置扫描。扫描含远程配置时可能连接目标；先在隔离 mock 和静态副本执行，核实命令的网络行为与目标范围。[R04]
- **A2A 规范仓库**：固定目标实现所支持的规范提交/版本，以自建 HTTP 测试 Agent 和日志适配器执行身份/上下文配对检查。未核实到可作为通用黑盒审计器的稳定官方 A2A 检查器；缺工具时用测试 Agent、代理日志和受控 HTTP stub 降级。[R05]
- **环境缺失降级**：没有 Inspector 时用 MCP SDK/协议仓库提供的客户端连本地 mock；没有网络追踪时在容器网络层记录 mock 域名请求。不可将扫描器判定直接升格为确证。

### 怎么判

- **grep/机械判定**：工具清单规范化哈希、字段差异、resource/audience 配置、授权日志是否含主体/范围/decision、mock sink 是否收到 Canary、是否发生未批准下游调用。机器命中只生成候选。
- **人工判读**：描述变更是否改变信任边界、上游委托是否符合授权意图、Agent Card 声明与实际身份语义、目标规范版本是否要求相应保护。
- **Confirmed**：服务端或受控 sink 日志证明错误受众/主体被接受并获得超出批准范围的 mock 资源/操作，或低信任工具变更绕过批准并触发受控效果；必须有请求 ID、身份/策略决策和效果证据互相对应。
- **Suspected**：扫描器报工具描述风险、清单发生变更但无执行/审批证据、模型声称执行了工具、模型文本中出现 Canary，或只有客户端提示但没有服务端状态。常见误报是合法工具版本更新、规范化差异、同名但隔离的不同服务器、只看到响应而未证明调用。

### 学什么

- MCP 官方授权安全注意事项定义资源受众、令牌校验和代理边界。[R01]
- OWASP MCP Security Cheat Sheet 讨论工具定义变化、工具输出不可信、权限最小化及工具清单审查；其扫描建议是筛查，不构成运行时证明。[R02]
- MCP Inspector 的 Releases/迁移说明可用于锁定当前调试器版本和 Node 运行要求。[R03]
- A2A 官方协议说明 Agent Card、安全方案与 Agent 间任务交互模型。[R05]
- MCPTox（AAAI 2026）以多个 MCP server 构建工具使用风险基准，研究复用重点是验证真实工具选择/动作而非模型口头回答。[R06]
- 工具描述投毒与工具实现/描述不一致研究可作为 Canary 变体来源；将论文里的实验转成无害 mock 操作，不能直接对线上工具重放。[R07]

## A13 Agent 记忆与目标完整性

### 怎么测

1. **写入路径枚举**：在测试账户与本地环境列出对话持久化、用户偏好、摘要/压缩、RAG/vector store、文件/笔记、工具自动写入、共享 Agent memory、缓存等读写入口。逐项记录写入主体、信任来源、租户/会话范围、保留期限、删除路径和检索入口。
2. **建立控制**：写入一条无害、可唯一识别的可信 Canary 记录，正向验证同账户同意的后续会话按设计可读；另开未写入的账户/租户作阴性控制，应无法检索。记下存储记录 ID/索引/事件，而不是仅凭回答。
3. **低信任污染模拟**：从明确的低信任输入路径写入另一条无害标记，设计只用于读取/偏好显示的后续任务；同时配置一个 mock 高影响工具，要求独立显式审批才能调用。跨会话检查低信任记忆是否改变目标、工具授权或主体，不运行真实邮件、支付、账号变更等操作。
4. **跨边界检查**：在会话 A 写入，在同用户会话 B、不同测试用户/租户 C、重启进程后分别检索。记录每个存储层/缓存的归属和读路径。不同任务本来共享同一授权知识库时，先确认策略而非直接定性泄漏。
5. **清除核验**：通过产品声明的删除控制删去 Canary，验证 UI/API、摘要、索引、向量库、缓存和重启后的检索都不再返回；检查删除事件的状态。若仅删除界面条目而后台索引不可见，只能标记验证缺口。
6. **停止**：发现测试 Canary 被非测试租户读取或影响真实目标/动作时停止，保护现场记录，不尝试继续提取记忆。

### 用什么

- **Promptfoo 0.126.0**：支持 agentic memory-poisoning、hijacking、cross-session-leak 等评测插件；npm/CLI 获取并固定版本。把 provider 指向本地模拟 Agent、测试租户和 mock 工具；默认不要将自动 red-team 流量指向生产。[R09][R10]
- **OWASP Agent Memory Guard 0.3.3**：开源 Python 工具/参考实现，可从 PyPI 固定版本安装，含记忆访问控制及 benchmark 相关组件。它适合评估本地防护设计，不证明目标实现安全；固定版本和 commit，审阅变更记录。[R11]
- **降级**：无记忆后端审计权限时，使用产品支持的导出/删除接口与唯一 Canary 进行黑盒验证；不能观察后端清理状态的部分明确记为“无法核实”，不依据模型回答判定。

### 怎么判

- **grep/机械判定**：存储日志是否带写入主体、来源标签、scope、时间、TTL、delete 状态；精确 Canary 是否跨会话/租户被检索；删除后所有已列读取接口是否仍返回精确标记。
- **人工判读**：记忆的授权来源和业务目标、摘要是否保留高信任字段、低信任事实是否合理影响回答、目标变化是否构成实际策略违背。
- **Confirmed**：低信任 Canary 跨租户/账户可读，或它使 mock 工具越过独立审批/授权条件；删除操作成功返回但存储/索引仍能让后续任务读取且超出声明保留策略。保存写入、读取、主体和影响的完整关联。
- **Suspected**：仅观察到跨会话记忆持久化（可能是设计预期）、模型复述 Canary 但没有后端检索证据、单次总结变化、删除界面不显示但索引不可观察。排除用户主动复制、共享知识库设计、缓存延迟和摘要合法保留。

### 学什么

- OWASP Agentic Top 10 2026 将目标劫持与记忆/上下文污染分别作为 Agent 风险类别。[R08]
- “Poison Once, Exploit Forever”研究环境注入型长期记忆污染；“From Untrusted Input to Trusted Memory”研究信任转换链；两者应转为合成记忆与 mock 效果测试。[R12][R13]
- AgentLAB（ICML/PMLR 2026）覆盖多类 Agent 攻击并使用长时任务/良性对照，适合借用配对实验结构。[R14]
- MemoryDojo（2026 年 11 月预印本）和 MemSecBench（2026 预印本）涉及长期记忆安全基准；属于预印本，结果和代码成熟度需独立核实。[R15][R16]
- MINJA（NeurIPS 2025）研究无直接数据库访问条件下的记忆注入路径，复用其“来源低信任输入→持久记忆→后续目标”的链式观察方法，不复用破坏性提示。[R17]

## A14 LLM 网关与策略链

### 怎么测

1. **画四通道 × 控制点矩阵**：对输入、检索文档、工具结果、模型输出分别记录入口校验、来源/信任标记、策略/权限检查、输出过滤、出站限制、错误/超时行为、审计事件。对每条通道标明组件、策略版本和 trace ID。只对客户配置中已声明启用的控制判定缺失。
   | 通道 | 入口/来源控制 | 策略执行点 | 效果/出站边界 | 必留事件 |
   |---|---|---|---|---|
   | 输入 | 网关接收、用户/租户身份、输入分类 | 输入安全策略、速率/权限检查 | 不应越过批准的工具/资源权限 | request ID、输入策略版本、allow/block |
   | 检索 | 文档来源、租户/ACL、索引与检索过滤 | 检索前 ACL、召回后信任标签/内容检查 | 只能进入当前主体允许的上下文 | source/doc ID、ACL 结果、检索策略版本 |
   | 工具结果 | 调用身份、工具来源、结果来源标签 | 工具后检查/策略再判定、是否允许继续调用 | mock 工具与 sink 确认是否产生受控效果 | tool ID、调用主体、结果分类、后续决策 |
   | 输出 | 模型/网关最终输出来源 | 输出安全过滤、结构/敏感字段检查 | 客户端展示及最终出站 sink | 输出策略版本、decision、告警 ID |
2. **通道探针**：为每个入口准备一对含无害 Canary 的测试样本和语义相近的正常控制样本。通过测试 API 分别注入；检索通道使用测试知识库文档，工具结果通道由 mock 工具返回，输出通道检查最终客户端响应和受控 sink。每条至少重复一次以排除偶发。
3. **防护阶段覆盖**：分别记录网关接收、检索、工具调用前、工具响应后、最终输出各阶段事件，确保输入过滤的成功不会被误认为工具结果也受检查。厂商文档对覆盖面有限制，例如部分 Guardrails 调用模式不检查工具结果/定义；Azure 文档说明某些 Agent 工具的干预仍是预览能力，须按实际调用方式核实。[R18][R19][R20]
4. **受控自适应测试**：先跑固定基线，再由人工测试者依据已观测的分类结果一次只改变一个特征；限制轮数、token/费用、时间与账号。只以 mock Canary 效果验证绕过，不尝试外送真实数据、隐藏监控或扩大权限。只在专用 staging 通过依赖注入模拟扫描器超时/故障，检查 fail-open/closed 是否符合书面策略；不得在生产制造依赖故障。
5. **遥测与告警**：在测试前登记预期事件和告警阈值。触发一条应阻断的 Canary 流程及一条无害正常流程，检查 trace 是否记录通道、策略/模型/配置版本、决策、原因类别和时间；确认阻断事件到达约定告警端，正常流量不会造成同类误报。不要为此要求记录原始敏感正文。
6. **停止**：意外触达真实工具/目的地、超出已批准轮数/成本、发现未知环境的生产 trace 或影响真实用户时停止；不得为追求绕过成功无限迭代。

### 用什么

- **Promptfoo 0.126.0**：可固定版本组织本地红队用例、回归和结果对比；通过自定义 provider/trace adapter 接客户 staging 网关。它不自动证明厂商控制点覆盖完整。[R09][R10]
- **厂商原生审计/控制台**：AWS Bedrock Guardrails、Azure AI Content Safety/Prompt Shields 等托管策略没有可通用比较的单一组件版本；记录部署区域、模型 ID/版本、策略 ID/修订、集成 API 和发布时间。目标环境无审计接口时，使用代理日志、mock 工具日志及网关 trace 关联。
- **研究基准**：自适应攻击实验只用本地 harness 和无害案例，不把论文攻击样本直接送到授权范围之外。[R21]

### 怎么判

- **grep/机械判定**：四通道覆盖配置表完整率、指定字段/trace event 是否存在、策略版本是否被记录、sink 是否收到 Canary、阻断告警是否在登记时间窗内生成。
- **人工判读**：语义过滤边界、正常/恶意样本等价性、自适应测试是否只改变一个变量、告警是否足以让运营人员定位事件、实际失效是否违反书面策略。
- **Confirmed**：经过批准应阻断的 Canary 在某一通道到达受保护 mock sink/工具效果，且 trace 证明控制链漏检或错误放行。无告警但请求仍被拦截应另记为可观测性缺陷，而不是访问控制绕过。
- **Suspected**：模型输出看似违反规范但无受控副作用、只检测到某层未记录、一次误拦截、供应商控制台状态与实际策略未交叉验证。排除模型非确定性、策略版本错配、客户端展示缓存及没有经过被测通道的样本。

### 学什么

- USENIX Security 2026 “The Attacker Moves Second”研究自适应攻击下防护评估的偏差，指出静态一次性评测不足；其统计结论不能直接推断任一具体网关必然失效。[R21]
- AWS 文档区分 Prompt Attack filter 与显式调用 Guardrail 检查的阶段；Azure Prompt Shields 文档说明 Agent 场景的工具结果覆盖依集成方式而变。[R18][R19][R20]
- Promptfoo 的插件/发布文档适合构造固定回归矩阵；版本更新可能改变行为，报告须固定 CLI 和用例版本。[R09][R10]

## D7 平台应用完整性与服务端判定

### 怎么测

1. **明确判定链**：为 Play Integrity 或 App Attest 记录客户端挑战请求、绑定字段、服务端 token/assertion 验证、应用身份/环境、nonce/hash/counter、缓存键、风险策略和最终服务端业务决策。挑一个仅影响测试 Canary 的读/写操作作验证目标。
2. **挑战绑定正控**：使用测试设备/应用、测试账户与服务端签发的一次性挑战。请求中应绑定应用、会话/主体、目标操作及业务对象标识（敏感业务字段仅用规范化哈希）；服务端校验完整请求后接受预定操作。Play Integrity Standard 应验证 requestHash 并按官方实现处理自动 replay protection；Classic 使用服务端 nonce。App Attest 使用服务端挑战及 clientDataHash 验证，并维护 key/counter 状态。[R22][R23][R26][R27]
3. **负控与重放**：在专用 staging 中逐项置换一个绑定字段、重放同一 token/assertion、复用/过期 challenge、提交错误应用/环境凭据、使用重复或旧 counter；每一项都应拒绝或走预先书面规定的风险降级。使用隔离的测试对象和一次性账号，不能重放影响真实业务的请求。
4. **缓存核验**：在相同请求、相同 nonce 但不同主体/操作、相同主体但不同对象三种情形下检查缓存命中键是否会复用验证结果。触发并记录一次正常缓存命中作为正控。除非测试服务可安全注入，不通过攻击生产缓存制造状态。
5. **降级测试**：仅在 staging 注入 provider 超时、设备不支持、缺失 token 等状态；核对高风险操作是否遵循书面 fail-closed 或有限降级策略。若设计允许风险评分，不把“未硬拒绝”自动判错，需与批准策略及业务授权结果比对。
6. **停止**：出现非测试业务操作成功、挑战/令牌可用于真实业务、provider 账户或密钥超出授权、意外触发真实账号风控时停止。

### 用什么

- **Google Play Integrity 官方标准/经典请求与 verdict 文档**：按官方文档接测试 Play Console/Google Cloud 项目；官方 Android security-samples 中 PlayIntegrityAPI 示例可作为客户端/服务端起点。示例仓库没有在此核实稳定语义版本，执行时固定 Git commit 和依赖锁文件。[R22][R23][R24][R25]
- **Apple App Attest 官方文档与 WWDC 说明**：服务端验证是权威依据，需验证证明签名、应用身份、挑战/clientDataHash 和计数器；Apple 文档与会话资料没有第三方“安全审计器”稳定版本可核实。[R26][R27][R28]
- **降级**：没有真实平台测试租户/设备时，先用本地 verifier 单元测试和签名测试夹具覆盖负控；这只能证明测试 verifier 逻辑，不证明线上服务端集成。

### 怎么判

- **grep/机械判定**：challenge 是否一次性消费、requestHash/clientDataHash 是否参与验证、挑战是否绑定目标操作/主体、缓存键字段、服务端是否检查签名和应用身份、拒绝事件是否记录 reason。静态代码存在校验调用并不代表调用链被业务端使用。
- **人工判读**：哈希序列化是否稳定、字段是否覆盖真正授权条件、counter 并发/重试策略是否符合服务设计、设备不支持的降级是否合理。
- **Confirmed**：服务端审计日志证明被置换/过期/重放的证据被接受，并使受控测试操作获得本应拒绝的业务授权。需把 challenge/token 哈希、请求绑定字段、后端决策及 Canary 效果关联起来。
- **Suspected**：客户端可 hook/绕过本地检查但服务端仍拒绝；只发现 SDK 未调用；误把设备 verdict 等同于用户身份；单个 counter 并发乱序但服务端拒绝的是合法请求。客户端绕过本身不确证服务端授权缺陷。

### 学什么

- Google 官方 Standard、Classic 和 verdict 资料定义 requestHash、nonce、重放防护与服务端解码校验边界。[R22][R23][R24]
- Apple 官方 App Attest 服务端验证与应用完整性文档，以及 WWDC 2026 对挑战绑定与单调计数器的说明。[R26][R27][R28]
- Google 官方示例仓库提供集成样例；应将示例视为起点而非目标实现的安全证明。[R25]
- AttestLens（WiSec 2026）研究 App Attest/完整性机制采用与集成实践；论文适合指导“SDK/API 出现”与“服务端真正判定”分层核验。[R29]

## D8 隐私清单与 SDK 数据行为

### 怎么测

1. **构建声明基线**：对签名归档、包、嵌入 SDK 逐一保存 Apple Privacy Manifest、Required Reason API 声明、Xcode 隐私报告、依赖/SBOM、Android 权限/SDK 清单和隐私政策版本。明确 target、build number、SDK 版本、动态/静态链接和平台系统版本。
2. **静态对照**：逐项关联 Required Reason API 调用、第三方 SDK manifest、收集的数据类别/用途、权限和政策披露。检查缺声明、SDK 声明冲突、构建产物缺 manifest 等机械候选；随后人工确认该 SDK/API 是否在目标构建中可达、用途是否真实。
3. **动态观测**：用专用设备和合成用户资料执行首启、拒绝同意、同意、撤回/关闭、后台/冷启动等路径。以 mitmproxy 或等效 TLS 代理记录域名、时间、请求大小和经过脱敏的结构；对自有测试构建中实际触及的 Required Reason API，记录调用栈/模块和对应 manifest 声明。结合 SDK 模块、线程、OS 隐私报告与测试构建中逐项禁用 SDK 的差分来归因。代理看到某厂商域名本身不能证明哪个 SDK 发起请求。
4. **网络与归因正负控**：先运行不触发目标 SDK 的空白控制，再触发测试 SDK 明确记录的合成事件；比较目的域名和调用栈。仅在用户自有设备/构建启用应用级观测，不对证书固定的第三方线上服务做绕过。涉及数据最小化时只比较合成字段，不传真实身份信息。
5. **Android SDK Sandbox**：先核实目标 Android API/runtime。Android 官方参考目前将 SDK Sandbox API 标为 API 37 deprecated 且不再支持；故仅对实际仍使用该运行时的系统/设备按目标版本测试。用自有 demo SDK 检查 load/unload、宿主↔SDK IPC 参数、权限/数据访问和回调边界；不要把旧 API 设计当成新系统的默认隔离保证。[R37]
6. **停止**：发现真实个人数据或敏感标识离开测试设备、请求发往未批准第三方、无法区分测试与真实账户流量时立即停止并隔离样本。

### 用什么

- **Xcode 27**：从 Mac App Store 或 Apple Developer Downloads 获取，用于苹果隐私 manifest、Required Reason API 和归档 Privacy Report 核验；记录具体 Xcode build、SDK、archive hash。Xcode/SDK 是滚动发布，报告生成结果不代替行为观测。[R30][R31][R32][R33][R34]
- **MobSF 4.6.9**：2026-11-18 GitHub 最新 release，可从 GitHub Releases/Docker 获取，用于 iOS/Android 静态分析并提供部分 Android 动态监测能力。它输出候选项；不要上传含真实密钥或生产数据的包到公共扫描服务。[R35]
- **mitmproxy 12.3.1**：官方 release 2026-10-25，适用于受控代理与流量元数据留存；安装源见官方下载页/GitHub。TLS pinning 或不可解密流量应降级为 DNS/连接元数据、设备侧日志和测试构建调用栈，不绕过非自有服务保护。[R36]
- **Frida 17.27.4**：可在客户自有 iOS/Android 测试构建与授权设备上记录指定 API/模块调用栈；按官方 PyPI/GitHub 安装说明固定 host 与设备端版本。无注入权限时用 Xcode/Android 调试日志、OS 隐私状态和可控 SDK 开关做差分，不为观察而关闭设备安全保护。[R61]
- **Android SDK Sandbox API**：只针对相关历史/目标 Android API 版本和自建测试 SDK；API 37 已 deprecated，若目标没有实际使用则记录“不适用”，转为测试一般 SDK/IPC 边界。[R37]

### 怎么判

- **grep/机械判定**：manifest plist/JSON 字段、Required Reason API 调用与声明清单差异、包内 SDK/权限、网络域名/时间、合成 Canary 字段是否外发、用户授权状态对应的 API 调用事件。工具应保留源文件/包 hash 及精确命中位置。
- **人工判读**：SDK 域名归因、字段可识别性、声明与真实目的的一致性、拒绝/撤回后的允许行为、隐私政策措辞是否充分。流量归因要有调用栈、模块/线程、可复现实验差分或厂商日志之一，域名/IP 归属不足以确证。
- **Confirmed（技术）**：受控运行证明未授权的合成敏感字段被目标 SDK/宿主传至未批准目的地，或声明/权限 gate 的缺陷导致可复现数据收集；有设备事件和网络证据关联。
- **Suspected（技术）**：manifest 缺项、SDK 清单/政策不一致、某 SDK 相关域名出现但不能归因、明文网络请求未证明含敏感信息。声明或备案不匹配单独记治理差异，不自动称技术漏洞。

### 学什么

- Apple 官方 Privacy Manifest、Required Reason API、第三方 SDK 要求和 Xcode Privacy Report 文档定义静态核验材料。[R30][R31][R32][R33]
- Xcode 27 release notes 用于匹配归档工具链和 SDK 版本，测试报告需记录实际 build。[R34]
- Android 官方 SDK Sandbox API 参考明确当前 API 状态，避免把历史隔离架构误用于现行版本。[R37]
- Panoptes（PETS 2026）研究异步/第三方组件的数据流归因；其 GitHub 项目可供研究性复现，执行时须锁定提交并只测自有构建。[R38]
- 2024 以来 Android 第三方 SDK 隐私研究可帮助设计 SDK 清单、流量归因和差分观察；研究样本结果不代表目标应用行为。[R39]

## W7 平台登录态与身份绑定

### 怎么测

1. **测试账户和后台基线**：由客户准备同一小程序/App ID 下的测试账号 A、B、测试资源 A/B 和非生产后端。记录平台 code 换取接口、服务端 session 建立、用户主键映射、刷新/注销策略。微信 code、抖音 code2session、支付宝 authCode 是不同产品流程，按目标版本官方说明，不假设生命周期完全相同。
2. **正向链路**：测试账号 A 在授权页面取得新 code，交给自有后端；核对服务端换取结果对应 A 的平台身份，应用 session 映射 A，A 只能访问 Canary-A。绝不把 session_key 或平台长期凭证返回客户端。[R40][R41][R42][R43]
3. **单次/过期/错误绑定负控**：在测试租户逐项测试已用 code 再次兑换、过期 code（优先在 mock 服务或本地时钟夹具验证；真实平台自然等待过期时只做少量请求）、A code 与 B 的应用 session/业务对象混用、错误 AppID/环境配置。预期应由平台/后端拒绝、幂等处理或保持原身份，不能静默绑定 B。
4. **会话撤销**：刷新/退出/撤销后重放旧应用 session，只请求 Canary 数据；验证旧 session 被拒或按书面策略限制。记录服务端 session 表状态，不以客户端页面跳转判定注销成功。
5. **停止**：授权码意外兑换为真实账号、资源映射到非测试用户、出现可疑真实支付/个人信息时立即停测并撤销测试凭证。

### 用什么

- **各平台官方 IDE、测试小程序与开发者控制台**：分别使用微信开发者工具、抖音开发者工具和支付宝小程序 IDE/控制台。抖音官方下载页截至研究日列出 4.5.7（2026-10-22）；微信/支付宝 IDE 本轮未核实到可稳定读取的当前版本页，微信下载入口需从官方开发者工具页面进入，支付宝从官方 IDE 文档进入；实施时记录具体构建号、基础库、AppID 环境和设备系统。[R59][R60]
- **mitmproxy 12.3.1**：仅观察自有后端 API 和测试租户流量；平台 token/code 按敏感数据处理并脱敏。[R36]
- **MiniAuth 研究**：借用其登录生命周期与身份绑定观察方法，不把论文描述当成目标小程序的适配审计器；可复用代码、稳定发行版及其对当前平台版本的适配状态未核实。[R44]
- **降级**：未获平台测试账号时，后端 mock 用不同 issuer/AppID、一次性 code、过期时间和身份映射覆盖服务端逻辑；报告区分“模拟验证”与“平台真实集成验证”。

### 怎么判

- **grep/机械判定**：服务端日志中的 AppID/issuer、code 交换结果主体、应用 session 绑定主体、旧 session 状态、客户端包中是否出现 session_key 等敏感字段。扫描日志前先脱敏。
- **人工判读**：平台身份到业务用户的映射规则、多平台账号合并/解绑策略、异常码重试是否产生账户覆盖。
- **Confirmed**：后台日志和资源读取证明 A 的一次性 code、过期/重放凭证或错误主体映射，令 A/B 资源被错误绑定或越权访问。单纯平台返回“code invalid”不构成漏洞。
- **Suspected**：只看到 code 可重放但后端幂等且不授予新权、前端登录状态异常、错误账户提示但无服务端映射证据。排除测试环境账号共用、服务端缓存延迟、平台正常重试与账户合并设计。

### 学什么

- 腾讯 CloudBase 微信小程序登录说明提供 wx.login code 一次性/有效期及服务端交换示例；针对实际平台版本复查官方规则。[R40]
- 抖音官方 code2session、登录链路与云函数身份说明定义 code 换取和服务端会话边界。[R41][R42]
- 支付宝开放平台 my.getAuthCode/服务端换取说明用于区分授权类型和服务端身份处理。[R43]
- MiniAuth 公开研究用于登录状态、绑定关系与平台差异的测试设计；研究产物可用性未核实，不依赖未确认工具。[R44]

## W8 宿主能力与跨小程序隔离

### 怎么测

1. **授权范围**：至少准备两个由客户控制、不同 AppID 的测试小程序/应用和一个专用宿主测试账号；若目标是宿主平台自身缺陷，另需平台方书面授权。记录平台、客户端/基础库版本、系统和登录态。
2. **Cookie/会话边界**：小程序 A 在客户拥有的测试 H5 域名/路径创建随机 Canary cookie，B 访问同一受控域名；正向控制在 A 的同一 WebView 中能读自身状态，阴性控制是不同域名、清洁配置或不同用户预期隔离。观察 Cookie 属性、域名、路径、WebView 实例、账户/宿主 partition 和实际请求，不用真实会话。
3. **宿主权限 API**：在自有测试包调用位置、相机等有明确用户授权状态的 API，分别测未授权、已授权、撤回后的返回值和系统权限状态；用无个人数据的传感器/虚拟数据。将小程序 JS bridge 调用和宿主/OS 权限事件按 trace/timestamp 对齐。
4. **负向跨应用探针**：从 B 请求 A 的 Canary 标识/会话，只验证受控资源是否返回，不遍历宿主文件、数据库或其他小程序。检查宿主是否把 A 的权限/身份误用于 B。
5. **工具覆盖降级**：首选官方开发者工具控制台/调试器、客户拥有的 Android 测试设备与动态事件监测；在授权测试设备上可通过 Frida 跟踪 bridge/API/系统调用，但要记录脚本和版本。若只能观察 JS 结果，缺少宿主/OS 事件关联时结论为疑似。
6. **停止**：任何真实用户 cookie/session、非自有域名数据、系统级敏感数据或其他小程序数据出现时停止，销毁测试会话并隔离样本。

### 用什么

- **PERMSCOPE（USENIX Security 2026）**：论文提出宿主 JS bridge 与 OS 权限调用联合分析；研究项目页面可查，但本轮未核实出可作为稳定发行版的公开二进制/CLI 和版本。复用其 API 映射与权限缺失检查思路，在自有测试包重建最小检查表。[R45]
- **CMCS/MiCoScan 研究**：ASE 2025 对跨小程序 Cookie 共享建模并做静态/动态研究；MiCoScan 可复用代码及当前平台兼容性未核实，不能因论文观测就推定所有宿主版本共享 Cookie。[R46]
- **开发者工具**：微信、抖音、支付宝工具版本滚动，按目标版本记录工具 build、基础库及设备；抖音官方下载页列出 4.5.7（2026-10-22），从官方页下载安装。[R47][R60] 支付宝 IDE 从官方文档中心获取，当前版本号未核实。[R59] 开发者工具调试不能替代宿主进程/OS 级追踪。
- **mitmproxy 12.3.1 / Frida 17.27.4**：前者用于自有域流量，可从 mitmproxy 官方下载；后者是截至 2026-11-21 的最新 release，host CLI 可经 PyPI 安装 frida-tools，设备侧组件从官方 releases 获取并匹配版本。仅对获批自有测试设备使用；若设备不支持注入，降级到开发者工具日志、OS 权限状态和 mock API 结果。[R36][R61]

### 怎么判

- **grep/机械判定**：小程序包/API 清单中的权限 API、跨应用同域配置、cookie 读写结果、权限状态和 bridge/OS trace 是否齐全。静态看到同一域名或 API 调用不能确证共享/越权。
- **人工判读**：目标基础库是否按设计共享域会话、宿主权限提示是否适用于当前 API/版本、用户授权是否可由业务目的支持。
- **Confirmed**：在两个受控 AppID 间复现 B 获取或使用 A 的合成 session/Canary，且服务器/WebView/宿主记录证明跨边界；或在拒绝/撤权后 B/调用方仍获得受保护的合成能力/数据。平台自身边界问题需平台授权才能确证归因。
- **Suspected**：两个 WebView 请求到相同域、工具提示相同 cookie jar、静态发现系统权限 API、单次 API 返回值异常但权限状态不明。排除同一 AppID 子页面、测试账号/配置误共用、合法域名 Cookie 设计及基础库差异。

### 学什么

- PERMSCOPE 2026 对微信、QQ、支付宝、百度等宿主 API 权限检查做规模化分析，论文报告的比例只反映其样本和版本。[R45]
- Cross Mini-program Cookie Sharing（ASE 2025）提出 CMCS/MiCoScan 对跨 WebView 域 Cookie 流建模；对目标运行时必须实测，不外推到所有平台版本。[R46]
- 研究代码/工具发布状态未独立核实；可复用论文实验设计，方法落地以双 AppID Canary fixture、宿主事件和自有域名为准。

## W9 云资源身份与部署边界

### 怎么测

1. **范围与环境清单**：客户明确云项目/环境、开发与生产分离、数据库/对象存储、函数、HTTP/event/timer 入口、服务身份/IAM、管理面和部署身份。没有管理面授权时只读导出配置，不验证或更改账号/角色。
   | 平台 | 客户端规则 | 服务函数身份 | HTTP/事件入口 | 管理面/部署 |
   |---|---|---|---|---|
   | 微信云开发 / CloudBase | 数据库规则、对象访问规则与实际数据库模式 | 云函数安全规则、服务端 SDK 身份 | HTTP API 函数、内部/定时触发分别列项 | 项目环境、角色、部署凭证；无授权只读 |
   | 抖音云 | 小程序客户端调用及云资源规则 | callContainer/云函数运行身份、IAM | HTTP、自定义域名、回调、事件触发分别列项 | 开发/生产环境、服务身份和发布权限 |
   | 支付宝云 | 以客户实际产品与 SDK 配置确认客户端授权规则 | 按实际函数产品确认运行身份/数据权限 | 逐项确认 HTTP/事件入口是否存在及其认证方式 | 保存控制台策略和部署主体；公开机制未核实的格子标“未核实”，不补猜测 |
2. **Canary 对象**：在独立测试集合/桶建立不含敏感数据的 CANARY-W9 对象，A/B 两个测试主体各有自有对象。A 读自身对象作阳性控制；B/匿名访问 A 对象作阴性控制。写操作仅限可销毁的测试记录，验证后清理。
3. **分入口矩阵**：分别执行客户端 SDK 直连、云函数服务身份、HTTP 触发器、事件/定时触发器、管理面配置五条链。逐条记录实际主体和策略：客户端安全规则、函数服务角色、HTTP 鉴权、回调来源验证、存储/数据库权限。不能用“客户端直连被拒”代替“服务端函数权限安全”结论。
4. **函数参数信任**：以 A/B/匿名调用测试函数，让函数通过已授权服务角色只对测试数据工作；检查资源所有权由服务端身份/查询条件确定，而非信任客户端传入的 owner/user ID。HTTP 触发器分别测无认证、有效测试认证、错误来源头/签名；只有平台文档支持的签名或服务端校验才视为身份依据。
5. **最小权限与隔离**：对服务角色使用云厂商权限模拟器/策略分析器做只读 can-i 或静态权限审查；若工具不支持模拟，比较角色策略和仅有 Canary 的测试资源范围，不实际枚举其他客户资源。开发环境误连生产只用可见的配置/测试路由证据确认，不发送写入请求。
6. **停止**：出现生产资源、真实对象或其他租户 Canary 时停止；不扫描云提供商地址空间，不枚举公开环境 ID，不试探其他客户项目。

### 用什么

- **腾讯云开发/CloudBase**：官方数据库安全规则、云函数安全规则和 HTTP API 文档分别用于构建入口矩阵。新旧环境/数据库模式的策略可能不同，应固定环境和 SDK。CloudBase CLI 当前文档标注主版本 v3，可用 npm 安装 @cloudbase/cli 并通过 tcb -v 记录精确版本；使用最小只读授权，不能用部署身份执行只读审计。[R48][R49][R50][R62]
- **抖音云函数/服务**：官方文档覆盖函数、HTTP/event 触发、开发/生产环境、服务身份/IAM 及入口控制；工具版本滚动，按目标控制台和开发工具记录构建。[R51][R52]
- **支付宝云**：公开平台资料不足以核实当前云服务产品、管理面/IAM 与触发器的统一矩阵。以客户实际合同产品、控制台导出和服务端身份配置为依据；缺少可审计公开资料的检查项标“未核实”，不推断产品安全机制。
- **ICREMiner**：NDSS 2026 论文和公开 DOI 适合借鉴资源/调用链定位与零泄漏探测思路；本轮未核实到适用于当前三家云的稳定通用发行版。缺研究代码时使用源代码 grep、官方策略导出和测试 Canary。[R53]

### 怎么判

- **grep/机械判定**：客户端规则/云函数配置/HTTP 鉴权/触发来源/角色权限/环境变量清单、函数中对身份字段的引用、测试对象读写结果、服务身份日志。扫描器或配置策略命中应说明对应入口。
- **人工判读**：权限是否超出业务必要、服务端如何映射主体、回调来源如何认证、环境隔离与部署审批是否符合客户基线。单纯高权限角色需在模拟器或限定资源中验证实际范围。
- **Confirmed**：服务端 trace 证明 B/匿名主体通过某入口读取 A 的 Canary，或在测试 Canary 上执行超出批准范围的更改；记录入口、调用主体、服务角色、授权决策和对象效果。服务角色宽权限可作为已确认的配置过度授权，但若未验证有效资源范围，影响结论标疑似/配置风险。
- **Suspected**：公开 AppID/envID、客户端可见函数名、静态宽 IAM、客户端规则关闭但无实际越权对象、来源头单独缺失但平台可能有上游签名校验。排除开发/生产模式差异、数据库 RLS 与 JSON 规则差别、后台管理员预期权限和测试账号角色不一致。

### 学什么

- ICREMiner（NDSS 2026）研究小程序云服务资源管理错误，提出静态/动态结合及 zero-leakage probing，适合借用“资源来源→调用主体→最小 Canary 证明”的链条。[R53]
- CloudBase 官方文档明确数据库规则、云函数规则与 HTTP API 是不同入口，后台/服务身份调用不能仅凭客户端规则判断。[R48][R49][R50]
- 抖音官方云函数文档分别说明入口类型、环境和服务授权；请求来源标记应按官方机制校验，不能把一个可伪造的 HTTP 头当作充分认证。[R51][R52]
- 支付宝云侧当前管理面/服务身份文档公开可查性不足，需在客户提供的实际产品文档、控制台与测试租户中补齐。

## W10 备案与隐私治理证据

### 怎么测

1. **固定对象**：记录小程序 AppID、平台、运营主体、版本/基础库、备案/平台审核状态、隐私政策版本、收集字段/用途、SDK 清单、隐私接口声明、用户授权 UI 和删除/撤回入口。
2. **备案核对**：仅核查客户自有小程序的备案状态。将主管平台公开查询结果、平台控制台状态、应用内展示信息和当前版本/主体做日期化截图/导出；记下查询入口、结果时间和无法核验项。不批量抓取第三方备案数据。
3. **隐私接口状态**：在测试账号分别走首次启动、展示授权说明、同意、拒绝、再次请求、撤回/设置变化等路径。记录平台状态 API 和实际接口调用/回调结果。抖音文档描述 getPrivacySetting、onNeedPrivacyAuthorization 等接口；微信 API 名称和支持版本需按目标基础库官方文档复核，不因接口同名推断行为一致。[R56]
4. **一致性矩阵**：把备案/隐私政策写明的主体、字段、用途、第三方 SDK、保留/删除说明，与小程序声明、权限调用和 D8 动态 Canary 观察并列。明确每个差异是治理文件差异、技术行为，还是尚待隐私/法务评审。
5. **证据模板**：对每项差异保存声明原文位置/版本、平台状态、测试步骤、结果、时间、证据 hash、客户解释、复核负责人和整改期限；截屏遮蔽用户标识、验证码与授权码。
6. **停止**：遇到非测试用户的授权记录或实际个人信息时停止；不做法律合规结论，不替客户提交或变更备案/政策。

### 用什么

- **工信部公开备案查询**和平台自有控制台：工信部备案管理通知给出小程序平台备案制度背景；公开查询结果须与客户主体和版本证据核对。[R54]
- **抖音开发者文档**：备案说明及隐私授权/隐私政策状态接口可作为目标平台流程核验来源。[R55][R56][R57]
- **微信隐私授权文档**：腾讯云文档说明平台隐私接口与用户授权状态关系；本轮未能核实微信官方文档的稳定直达路径与当前所有基础库 API，实施时从开发者工具/官方文档导航复核 API 名称和最低版本。[R58]
- **降级**：平台账号权限不足时只使用公开备案查询、应用包和经客户提供的控制台证据；无法取得后台状态时不推断“已备案/未备案”。

### 怎么判

- **grep/机械判定**：AppID/主体/备案号字段是否存在、政策/SDK/权限声明版本是否完整、包内 SDK 和 API 候选清单、隐私接口授权状态事件是否记录、证据模板必填项是否缺失。
- **人工判读**：政策文字是否充分、目的/字段是否合理、备案主体与实际运营关系、SDK 处理者角色、法定义务与整改优先级。技术人员只报告事实与差异，不出具法律意见。
- **Confirmed（治理差异）**：经客户和平台证据复核，备案/政策/SDK 声明与当前自有版本存在可定位的不一致，记录为治理/披露发现；该分类不等同技术漏洞或法律违法结论。
- **Confirmed（技术）**：只有当测试证明隐私授权 gate 可被绕过并导致受保护 API/数据在拒绝授权状态下实际发生时，另按 W8/D8 的技术判据定性。
- **Suspected**：公开查询延迟、主体更名待同步、截图缺日期、政策网页缓存、工具版本/API 名称不匹配。排除审核处理中、分阶段发布、平台缓存与客户主体合法变更。

### 学什么

- 工信部小程序备案通知和公开备案系统用于确定制度及查询证据范围，不足以代替法律审查。[R54]
- 抖音官方备案与隐私授权接口文档可用于测试状态查询、授权回调和声明维护流程。[R55][R56][R57]
- 腾讯 CloudBase 隐私接口说明可作微信测试线索；对目标微信基础库/API 版本仍须回到官方开发文档和授权测试账号验证。[R58]

| A14 | 通道覆盖、版本/trace 字段、阻断告警到达、Canary 到 sink | 多组件语义、adaptive 变体等价性、告警是否可行动 | P1 | 网关常见且影响面大；各产品 API/控制点版本差异大，自适应评估误报和成本较高 |
| D7 | challenge/hash/counter/cache 字段、服务端 decision 日志 | 请求绑定是否完整、错误凭证是否被业务授权接受 | P0 | 官方规范和样例清楚；后端测试租户可重复构造负控，授权判据确定，误报较低 |
| D8 | plist/manifest/权限/API 清单、包内 SDK、网络元数据 | SDK 流量归因、隐私目的与实际数据影响 | P1 | 静态工具成熟但行为归因难；隐私治理误报较高，需设备和合成数据 |
| W7 | code/session 主体映射日志、过期/撤销状态、敏感字段命中 | 平台 code 语义与后端错误绑定的真实影响 | P0 | 测试账号/租户可用且后端结果可判；跨平台代码差异需适配，整体影响明确 |
| W8 | API 清单、cookie/权限状态、事件关联字段 | 跨 AppID 实际读取/使用与宿主归因 | P1 | 研究方法有新成果但工具/版本碎片化；跨小程序测试需平台授权，误报风险高 |
| W9 | 规则/IAM/触发器配置、函数身份日志、Canary 对象结果 | 权限业务必要性、真实主体链和服务端效果 | P1 | 云厂商文档与客户测试项目可支撑，但多入口/多环境复杂，管理面授权是主要可达性门槛 |
| W10 | 备案/声明字段、证据项完整性、隐私状态事件 | 披露是否充分、法律义务与差异影响 | P2 | 公开查询和证据模板易落地，但治理结论需客户隐私/法务复核，不宜技术自动定漏洞 |

**建议实施顺序**

1. **P0（首批技能）**：A12、D7、W7。先固化共用证据 ID、测试账号/Canary 模板和停止条件，再写每项脚本适配点；A12 所有工具调用先指向 mock，D7/W7 的业务效果限定为测试对象。
2. **P1（第二批）**：A13、A14、D8、W8、W9。需要客户提供记忆后端/网关 trace/受控设备/云项目；将“能观察到的效果”和“只能静态推断的配置风险”分开报告。
3. **P2（治理模板）**：W10。先建立版本化证据表与治理/技术分流模板；如客户可提供平台账号和隐私负责人，再增加半自动采集，不将政策判断自动化。
