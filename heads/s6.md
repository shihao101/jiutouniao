# 阶段 6 · 后渗透与横向移动（POST-EXPLOITATION）

**目标**：从「立足点」扩大到「业务影响可达范围」，证明真实风险。进入条件：已获初始访问（S5 漏洞利用，或 S5-2a 浏览器合规登录——后者按 browser-auth 流水线先做 CLI 基线验证与端点清单入队，再进入本阶段）。

## 分步动作

1. **S6-1 权限评估与提升**：盘点当前权限；本地提权、云 IAM 提权、容器逃逸候选路径评估；产出《权限矩阵》。提权动作先审批。
2. **S6-2 内网探测与横向移动**：内网拓扑、凭据复用、SSRF 入内网、服务间信任滥用（含 AI 服务 → 内部 API）；LLM 推荐最短攻击路径；横向动作先审批，限速探测。Windows 环境按 load_skill windows-lateral 矩阵推进（netexec 枚举→PtH/WMI/WinRM 横向），域环境叠加 ad-attack；**横向前先查上下文包战利品与黑板**（凭据/已中继主机/签名状态），避免重复获取；拿到哈希/票据先按 load_skill password-offline 做离线可破解性证明（ROE 额度内）。
3. **S6-3 敏感数据访问证明**：定位 PII / 源码 / 密钥 / 业务数据，记录「可访问证明」——只截图/计数/哈希，**不带走数据**。
4. **S6-4 权限维持与钓鱼模拟（如授权）**：ROE 允许下演示持久化（load_skill persistence：per-OS 候选清单+四元组登记，心跳无害化）并逐项标注建议清理方法——**v4.8.1 口径：S7 只记录移交，不执行删除/重启/还原**（智能体产生的全部驻留包含但不限于上传类）；钓鱼模拟按 load_skill phishing-infra 口径——默认只做邮件域防护只读判定（SPF/DMARC），投递演练需 ROE+授权名单双重门禁。默认不做，需 ROE 明确允许。
5. **S6-5 云与容器逃逸专项**：初始立足点在容器/云上时，逐项过 privesc-checklist 的「容器/云」检查组（privileged/挂载 docker.sock/hostFS/实例元数据 IMDSv1/IAM 角色），候选路径先审批再验证。
6. **S6-6 存量持久化痕迹排查（拿到 RCE/落点后必做，v4.8.1 增补）**：对已获主机做**既有持久化面只读清点**（排查前人/第三方遗留的后门与驻留——与 S6-4 自建演示严格区分）：cron/at/systemd timer、SSH authorized_keys/known_hosts 异常、用户态启动项、新增/隐藏账号（uid≥1000 与影子账号）、异常监听端口与进程、web 目录可疑可解析文件（webshell 特征）、容器挂载异常、数据库作业/触发器。清单见 load_skill persistence 第五节。**口径：只发现、只登记、不处置**——逐项 record_finding（置信度=疑似/待查，detail 引用证据文件）+ 产出《存量持久化痕迹排查清单》`deliverables/s6-存量持久化痕迹排查.md`；确证为第三方后门的项列入《需人工清理清单》移交（存量数据绝对不动——loop-core 清理铁律，处置属客户环境运维决策）。
7. **S6-7 回环触发（必读）**：后渗透中新发现的信息是新一轮攻击面的输入——命中以下任一情形，调用 loopback 触发前置阶段补跑（引擎允许每项目最多 **3 次**，按价值排序使用，先在 timeline 记录候选再决定）：
   - 内网探测发现**范围外新资产/新服务/新端口**（存活但未侦察过）→ loopback 回退 s2（攻击面重映射）；
   - 新攻击面需要**漏洞发现级测试**（新 web 服务、新组件指纹、新登录口）→ loopback 回退 s4（原语凑链缺口见 capability-primitive-search 反向搜索）；
   - 凭据复用打开了**新的认证后功能面**且 S4 队列未覆盖 → loopback 回退 s4。
   回环补跑是全量重跑该阶段：先在该阶段交付物里写清「本次补跑聚焦点」，避免重复已完成工作。

## 交付物

- 《权限矩阵》《横向路径图》`deliverables/s6-横向路径图.md`、《数据访问证明》《持久化记录（如授权）》《钓鱼模拟结果（如授权）》。

## 红线

- 范围外内网资产一律不碰；所有写操作与横向移动必须审批；敏感数据只做存在性证明。

## v4.7 增补

- 开工先读 evidence/channel-status.json（K5 心跳产物，若存在）判定通道状态，再决定是否重复基线自检；原语图缺口项（primitive-chains.md）在本阶段按 impact 顺序消耗。

## 执行模式契约（v5.3.1，与 loop-core 规则 6 / policies/execution-profiles.yaml 对齐）

- 本阶段默认 **production_safe**：引擎逐动作强制（v5.3.1）——持久化植入、隧道驻留、新增账号在全部通道被确定性拦截；存在性证明（配置/进程/注册表只读取证 + 命令回显）即止；
- **isolated_lab**（须显式声明且可快照回滚）：S6-4 持久化演示、合成低权/高权账号、测试租户方可执行；收尾以**快照恢复**回收，不在目标上执行清理命令；
- S6-6 存量持久化痕迹排查口径不变：只发现、只登记、不处置（任何档位均不例外）；
- 两种模式共用同一高影响底线：不波及存量数据、不向公网分发测试产物（lab 档内也禁止）。
