# 专项 B1 · AI 针对 APP 的渗透测试（静态链 S1-S5 + 动态链 D1-D8）

**适用**：Android/iOS APP。静态链负责反编译审计、生成漏洞假设与 PoC 脚本；动态链负责运行时绕过、插桩与接口验证。**框架（v6.0.2 重基线，据 docs/调研报告_三大专项_20261120.md）：OWASP MASTG 2.0 / MASVS 2.1，弱点交叉索引 MASWE；旧版 checklist 电子表格不再作为唯一索引，控制-弱点-测试-工具按 MASTG 机器可读结构关联。**

## 版本基线（v6.0.2）

- **标准锁定**：MASVS 2.1.0（新增 PRIVACY 隐私控制组）· MASTG 2.0.0 · MASWE（弱点分类）；测试记录引用 MASWE/MAS-TEST 标识。
- **工具已验证版本矩阵**（以各发布页为准；测试报告记录实际使用版本与哈希）：jadx 1.5.6 · Apktool 3.0.3 · Frida 17.27.4 · objection 1.12.5 · MobSF 4.6.4。同一脚本在不同版本/设备组合上的结果不默认等价——脚本与插件按「工具版本 × 设备/运行时」归档。
- **平台核验项**：Google Play Integrity / Apple App Attest 服务端决策（见 D7）；Android Developer Verification 2026-09-30 起部分地区生效、2027 年起全球扩展——影响安装来源与测试包来源证明，按地区/商店/设备逐一核验，不笼统视为全球强制；Android SDK Sandbox 平台 API 与兼容库弃用状态按目标 OS 版本确认（见 D8）；Apple Privacy Manifest 与 Required Reason API 声明与运行行为比对（见 D8）。
- MobSF 仅作静态/动态辅助平台，自动扫描结果人工复核后才可引用，不直接当已确认漏洞。

## 前置契约（v5.3.0）

结构化登记：测试包来源（客户提供/合法测试包）、设备所有权、测试证书与信任配置、测试账号、设备网络隔离。缺失前置时静态发现保持"待动态验证"，不得升级为利用结论；设备端操作限客户/测试设备，结束回退本地配置。

## 流程语义（v6.6.0 SP-⑩）

- **编号消歧**：本节「静态链 S1-S5」与「动态链 D1-D8」为**专项内部链编号**，与流水线阶段 S1-S8 无关——覆盖登记、时间线、交付物一律用 specB1 阶段标签，叙述时避免与主流程阶段语境混淆。
- **早退分支**：开工先核验资产台账——项目无 APP 类资产时，按「前提不成立」如实收口（交付物写明豁免依据），**禁止虚构测试动作**；引擎收口门对该形态走豁免路径。
- **回环语义**：本阶段不会被下游阶段回环自动连带（spec 为并列专项非下游）——上游回环产生**新 APP 包/新移动资产**时，显式 `loopback(to_stage=specB1)` 或提请人工重跑；都不适用时 record_vt 移交（三选一留痕）。

## 静态链（假设生成）

1. **S1 获取与应用画像**：获取安装包并识别加固壳类型、原生/Hybrid/Flutter/RN 架构、第三方 SDK 与权限声明；**记录设备 OS 版本、目标架构、安装渠道、开发者注册/验证状态与完整性能力**。
2. **S2 反编译与目标定位**：apktool / jadx 反编译（`jadx -d out app.apk`，**版本按版本基线锁定并记录哈希；Android/iOS 分别定义可复现路径**）；定位登录、支付、加密、网络通信等关键类与入口。
3. **S3 AI 代码审计**：逐类扫描：硬编码 AK/SK 与密钥、加密与签名算法还原、WebView JS 桥与 file 域配置、导出组件与 DeepLink、业务越权假设；语义过滤误报；**以 MASVS 2.1 / MASTG 2.0 / MASWE 作控制-测试-弱点交叉索引，补充隐私控制（MASVS-PRIVACY）、第三方 SDK、iOS Privacy Manifest 与 Required Reason API、Android SDK Sandbox 适用性及数据流一致性检查**。
4. **S4 AI 生成验证脚本**：由审计发现自动生成 Frida Hook 脚本、请求构造器与 PoC，逐条标注预期结果与判定条件；**按 Frida 版本与设备/运行时组合归档——Hook 能力本身不是漏洞证据**。
5. **S5 假设队列输出**：静态结论全部标记为「待动态验证」假设，按风险排序移交动态链——静态不下最终结论，避免误报；**假设附 MASWE/MAS-TEST 标识、复现条件与适用平台版本**。

## 动态链（运行时绕过 · 验证利用）

1. **D1 环境构建与检测绕过**：root/越狱设备 + Frida 注入；生成并迭代绕过脚本：root、模拟器、代理、证书绑定（SSL Pinning）检测；**开工预检（v6.6.0 SP-⑨，先于一切动态动作）**：`adb devices`（设备在场）→ frida-server 连通探测（`frida-ps -U`）→ mitmproxy 证书安装确认——任一失败 → 前置契约登记「设备不可用」，静态链结论按「待动态验证」移交（needs_follow_up 四元组），**不空烧动态链轮次**；**同时验证服务端如何实际使用 Play Integrity / App Attest 的挑战、令牌与风险信号——客户端检测绕过本身不等同于服务端授权缺陷**（深入项见 D7）。
2. **D2 抓包与接口提取**：mitmproxy 采集流量；解析请求，自动提取接口、参数与签名规律，生成可重放清单；**补充代理 pinning、证书/密钥轮换、TLS 行为与服务端完整性决策的观察**。
3. **D3 运行时插桩**：Hook 加密/签名函数，还原运行时算法、密钥与协议细节；与静态结论 diff，修正误判；**固定 Frida 客户端/主机工具版本；重点确认密钥边界、签名新鲜度与服务端验证，不采集真实用户密钥**。
4. **D4 AI 接口测试**：自动执行未授权/越权/ID 遍历/重放（严格限频、测试账号）；比对响应差异判定漏洞成立；**按 MASVS 2.1 / MASTG 2.0 结构记录认证、会话与服务端授权证据**。
5. **D5 行为与数据监控**：采集本地存储/logcat/内存快照，聚类敏感信息（密钥、token、PII）与泄露路径；**增加隐私数据最小化、SDK 数据收集、剪贴板/备份/截图等本地暴露面，以及隐私清单声明与运行行为一致性核对**（深入项见 D8）。
6. **D6 结论合并与汇入**：合并静态假设与动态验证结果，去重定级后汇入主流程阶段 5-8；复测时两条链回归；**代码层缺陷、平台策略信号与服务端实际安全决策分开记录**。
7. **D7 平台应用完整性与服务端判定（v6.0.2 新增）**：评估 Android Play Integrity、Apple App Attest 等信号的挑战绑定、服务端验证、重放/缓存/降级处理，及其对高风险业务操作的实际授权影响。
8. **D8 隐私清单与 SDK 数据行为（v6.0.2 新增）**：对照隐私清单/权限声明/用户告知与运行时数据流，识别第三方 SDK 的采集、共享、保留与退出/删除路径；适用时评估 Android SDK Sandbox 的数据/IPC 边界；以测试数据与经授权设备验证。

## 交付物与多目标分组（v6.6.0 SP-①）

- 核心交付物写入 `deliverables/`：《应用画像与反编译审计记录》《假设队列》《动态验证记录》等按链产出；收口交付物须含《专项条目清单》（静态链 S1-S5 + 动态链 D1-D8 逐条三态：已测（update_coverage 引用）/ 不适用（依据）/ 未测（原因+移交去向））。
- **多目标分组产出约定（v6.6.0 SP-①，与 s4.md S4-9 同族口径）**：按目标组（每个 APP/每个目标应用）推进时每组结论写 `deliverables/specB1-<目标或组名>.md`（含该组静态假设、动态验证结论与待续项），S8 报告承接合并；收口前逐组核对 update_coverage 已登记——引擎专项逐目标对账门按目标归宿拦截（与 S4-9/S5 同口径）。

## 收口确定性门（v6.6.0 SP-②）

- **开工即登记前置契约**（引擎收口门核验留痕，缺失拦截）：①测试包来源（客户提供/合法测试包）；②设备登记（测试设备所有权、root/越狱状态、测试证书与信任配置）；③测试账号。**v6.8.0 增补：动态链设备侧工件同步登记**——frida-server 推送、mitmproxy/CA 证书安装、测试包安装等设备侧留痕逐项登记四元组（位置/指纹/建议清理命令/验证命令）入《动态验证记录》（设备属测试环境，登记留痕即可、不要求处置）——S7 清理对账的输入侧由此覆盖专项链。
- **收口确定性门三件**（complete_stage 时引擎机械核验）：①前置契约三要素登记留痕；②核心交付物存在（**《假设队列》或动态验证记录**其一）；③《专项条目清单》存在（静态链 S1-S5 + 动态链 D1-D8 逐条三态——引擎只查清单存在，完整性由反思门抽查）。缺失前置时静态发现保持「待动态验证」，不得升级为利用结论。资产台账无 APP 类资产时走豁免（前提不成立如实收口）。
- **V3 双清单（v6.6.0 SP-③，引擎强制）**：静态链产出的 Frida 脚本/请求构造器/PoC 逐条将就绪资产路径写入 `record_vt ready_assets`；**未投递的假设队列项收口进 `ready_but_unexecuted`**（每条附就绪资产路径与启动条件），`l2_approved_unused` 无内容传空数组 []——S5 开工经「专项就绪移交」块承接，静态假设静默蒸发 = 交付缺项。
- **反思门专项核查（v6.6.0 SP-⑧）**：反思门会对本阶段按清单专项核查——①静态发现是否全部标「待动态验证」且假设队列已移交（静态直升确证即 BLOCK）；②客户端检测绕过是否被单独确证为服务端授权缺陷（缺服务端判定证据即 BLOCK）；③Hook/抓包/脱壳产物是否仅用于授权测试且未分发。被拦截需按意见修正后重提。

## 红线

- 仅用测试设备与测试账号；绕过与爆破严格限频；**支付/下单等写操作先审批**；脱壳与 Hook 产物仅用于授权测试、禁止分发。
