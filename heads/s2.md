# 阶段 2 · 信息收集 / 侦察（RECONNAISSANCE）

**目标**：在不触碰或轻触碰目标的前提下，画出完整攻击面，为威胁建模供给「原材料」。

## 分步动作（先被动后主动）

1. **S2-1 被动：域名与子域名枚举**：crt.sh、DNS 记录、历史解析，聚合去重；登记域名类资产。
2. **S2-2 被动：OSINT 情报收集**：公开代码库泄露、网盘与文档泄露、招聘与技术博客、组织架构与邮箱格式；产出《泄露与情报报告》。
3. **S2-3 被动：空间测绘**：如具备 API Key，可查 Shodan/FOFA/Quake/ZoomEye 指纹与历史端口服务快照；无 Key 时跳过并说明。
4. **S2-4 被动：凭据泄露查询**：范围内邮箱在公开泄露库中的命中；**仅记录不撞库**，登记为待查线索。
5. **S2-5 主动：端口/服务/指纹**：确认 ROE 时间窗口后，用 nmap 等做端口与服务识别——先 `nmap -sV -Pn --top-ports 1000 <目标>` 快速摸底，**在条件满足时升级 `nmap -Pn -p- <目标>` 全端口扫描（T2，v5.3.0 策略档：端口扫描已授权+时间窗允许+速率预算有余量才执行；不满足时记 deferred/ROE_excluded，不以缺扫描推断无服务）**；对已确认开放端口做 `-sV` 版本识别；httpx 存活与 Web 指纹、目录与 API 参数枚举；控制速率。**多目标批量：存活/端口/指纹全部用 `-l targets.txt` 批量形态单轮完成（宪法速度纪律 7）；指纹齐全后按 anon-attack-surface 总表逐族批量普查匿名暴露面（结果逐族 update_coverage）。实测不可达/纯静态的目标降级为**档案目标**——写入资产台账与本阶段交付物即止，不再进入 S4 深挖队列，轮次让渡给活目标。**
6. **S2-6 主动：AI 入口探测**：识别聊天入口、OpenAI 兼容模型 API、Agent/插件特征与模型行为指纹；登记为 AI 应用资产。
7. **S2-7 前端与 JS 情报（必做）**：抓取主站与登录页 JS bundle（含 .map/source map 残留），提取隐藏接口、API 端点、注释中的密钥/内网域名（LinkFinder/jsluicer 或 grep 正则），接口清单并入攻击面地图；source map 泄露本身登记为发现。
8. **S2-8 版本→CVE 预检索（必做）**：对全部带版本指纹执行已知漏洞预检索（load_skill cve-weaponization → searchsploit/NVD），产出《已知漏洞候选清单》移交 s3/s4——这是测试计划的一等输入。
9. **S2-9 目标自述面清单（条件必做）**：目标若**自述了能力面/漏洞面**（在线平台导航逐项命名功能与漏洞类型、API 文档端点目录、CMS 功能模块清单、首页功能栏目等——与目标类型无关，任何"自己列出了功能清单"的目标都适用），抓取并逐条结构化落盘到工作区根目录 `checklist.json`（write_file）：`{"items":[{"id":"C1","item":"条目原文","hint":"位置/路径","class":"漏洞类推断"}]}`（上限 100 条），同步以可读表格写入《目标自述面清单》交付物——该清单是 S3 测试计划与 S4 覆盖完整性对账的**覆盖下限**（不是测试目标，清单外盲挖照常执行），S4 收口时每条必须「覆盖登记引用条目文本/ID」或「显式 status 处置」；目标无自述面时不产出该文件（门自动不生效，五轨深挖协议照常）。

## 交付物

- 《资产台账 V1（域名/IP/服务/版本）》《攻击面地图》`deliverables/s2-攻击面地图.md`、《疑似泄露凭据清单》《AI 应用入口与模型接口清单》；目标有自述能力面时另产出 `checklist.json`（S2-9）与《目标自述面清单》。

## AI 增强点

- 批量阅读 OSINT 文本抽取实体与凭证线索；自动生成搜索 dork；汇总攻击面地图；扫描结果去噪与优先级排序。

## 执行要点

- 主动扫描必须在 ROE 时间窗口内，控制并发与速率；测绘平台数据可能过期，关键结论需现场复核。

## v5.4 S2 增补（架构信号→强制 VT + 运行时拓扑重建）

- **S2-10 架构信号→强制 VT 登记（必做）**：架构确证（含初步确证）命中下列信号时**当场** record_vt（Priority=1）并 upsert_fact（key=arch.signal，值=信号+VT 编号）——①前置网关统一路由+多异构后端 → VT「request-smuggling TE/CL 变体+vhost 模糊+内网拓扑向量枚举」（load_skill request-smuggling / intranet-lateral）；②JWT/会话令牌机制或密钥材料泄露（预览/部分密钥） → VT「jwt-crypto 全算法族可利用性裁决（alg 置换/算法混淆/kid 路径类/jku-jwk/密钥派生可行性），禁止只做离线爆破」；③SSO/票据/扫码登录机制 → VT「SSO 滥用矩阵：票据重放/固定/跨用户消费/QR 参数操纵」（load_skill auth-flow-deep）；④同应用多实例/多节点 → VT「instance-diff 行为差分矩阵」。S4-7 排序必须先消费本类 VT（引擎冲刺消息按 Priority 排序枚举，见 v5.3.9 批次④）。
- **S2-11 运行时拓扑重建（活交付物，必做）**：创建 `deliverables/拓扑重建-V1.md`，四源累积——响应头指纹（Server/节点标识/缓存特征）、错误页指纹（栈特征与上游线索）、JS 与配置文件内网引用、同源多端口行为差分；S4/S6 发现即增量回写（V1→VN 递增版本），S6 横向与 S8 影响评估必须引用最新版；S3 威胁建模以拓扑重建为 DFD 校准输入。
