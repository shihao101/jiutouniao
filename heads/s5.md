# 阶段 5 · 漏洞利用与渗透（EXPLOITATION）

**目标**：证明漏洞真实可利用，拿到「立足点」，全程留证。进入条件：待利用队列非空、高危审批通道就绪。

## 分步动作

1. **S5-1 目标选择与利用规划**：按队列优先级选择目标——**队列按 S4-7 标注的 impact-rank 升序消费（RCE 系 > 认证绕过 > SQLi 提数 > SSRF > 上传），无凭证项目优先消费 access=anonymous 的高危项**；规划**最小影响**的利用方式与回滚方案；产出《利用方案》（需人工批准后执行）。**队列只有零散低危时**：load_skill capability-primitive-search 按 RCE 六等式做凑链规划（READ/WRITE/SSRF/CRED/AUTHZ 原语组装），把「凑链缺环」作为利用目标，而不是直接宣告无可利用项。
   **v5.1.3 承接反蒸发（硬规则）**：承接 S4 `ready_but_unexecuted`/待利用队列做改写（合并/换编队/让位）时，**逐条三态映射——执行 / 合并进新编队（写明新编号）/ 显式移交（进待续清单）**，禁止静默丢弃任何条目；改写后计划必须与 S4 清单一一对应（S8 复核按此对账，实战实证 TH-23/24 高价值候选曾因改写静默蒸发）。
2. **S5-2 PoC 生成与本地验证**：用 write_file 生成载荷与 PoC（Python/Shell），先在本地/受控环境验证逻辑，再作用于真实目标。**利用/验证前置依赖登录态时，先 load_skill session-state-chain 按决策树路由（有凭据→登录链 jar 复用→带态测试→清理；无凭据→默认 deny 下禁止注册，走身份索取闭环，见 S5-2a）**——路由走完仍无身份才降级 premise_failed，禁止未走链就放弃登录态测试项。**SQL 注入手工确证/疑似 ≥2 个端点时必须按 sqli-deep「自动化批量扩展」过 sqlmap 批量提取（统一四件套 banner/user/db/is-dba），禁止只深验 1-2 个**。
2a. **S5-2a 认证获取（browser-auth）**：登录面命中 JS/WASM 加密、动态挑战 token、验证码渲染、UA 指纹过滤任一特征，或明文构造连续 2 轮失败时，**停止明文构造**，load_skill browser-auth 走真实浏览器合规登录（`/opt/tools/browser-kit/`，凭据只走环境变量；验证码 exit 42 → request_user_input 人工读码，禁止自动打码）→ 抓取 cookies/storage/端点清单 → CLI 接管执行测试主体；协议逆向（wasm2wat）降级为可选深挖项，不再是登录前置。失败额度与 curl 尝试合并统计。**v5.1 身份政策**：无凭据时按 identity-bootstrapping——L1 注册面只评估不注册（ROE `identity.auto_register` 默认 deny），身份索取闭环（request_user_input 向客户索要测试账号）走完仍无身份才允许认证后项 needs_follow_up 移交；**会话伪造合规边界：仅基于已确证伪造漏洞构造自有会话（L5/L6），禁止窃取/重放真实用户活跃会话**。
3. **S5-3 审批与受控执行**：写操作/RCE/横向等高危操作全部经审批矩阵批准后执行；全流量经代理并记录。3b. **落点管理**：拿到执行/写盘能力后按 load_skill webshell-memshell 做落点选择与登记（四元组：路径/指纹/建议清理命令/验证命令，写入《上传文件记录清单》）——**v4.8.1 口径：上传走渐进验证（先常规文件类型再可执行脚本），全部驻留只记录移交、不执行删除/重启/还原**，需要多轮交互的服务（数据库客户端/监听器）用 shell_open 会话而非反复 run_command。
3a. **利用选型降级链**：msf/searchsploit 现成模块验证（先本机复现载荷逻辑）→ 公开 PoC 适配（逐行读懂再改，禁止盲跑）→ 自写 PoC（load_skill poc-template）。每级产物受控验证后才能打靶。
4. **S5-4 AI 控制面利用（AI 目标）**：提取系统提示、绕过安全策略、经提示注入驱动工具调用越权（详见专项 A 的 A3-A7）。
5. **S5-5 凭据获取与会话接管**：从漏洞、配置错误与泄露数据中获取凭据，验证横向复用面；**凭据只登记摘要，不存明文**——一律 record_loot（掩码+来源+verified 状态），凭据相关结论同步 upsert_fact，S6 横向优先消费战利品库。
6. **S5-6 记录与回环**：每次利用记录：时间/载荷/结果/截图；发现新攻击面（新端口/新服务/新接口/内网可达面/新组件指纹）则 loopback 回退阶段 4 补充分析——宁可回环一次，不留「看到了但没测」的尾巴。工作区存在 `checklist.json` 时：本轮对清单条目的利用/验证同样按 S4-8 口径在 update_coverage 引用条目文本或 C 编号（s5 收口时 G2 门同 s4 口径对账）。
7. **S5-7 失败反馈环（必做）**：利用失败按原因 update_coverage——waf_blocked（记录拦截特征，可 load_skill waf-fingerprint 调整载荷后重试一次）/ patched（回写 s4 排除）/ premise_failed（回写假设修正）；同一目标×载荷最多重试 2 次。

## 交付物

- 《已验证漏洞 + PoC/截图》《初始访问（权限/会话）》《利用时间线》；新发现漏洞（回环阶段 4）。

## Agent 执行循环

每轮：选目标 → 生成 PoC → 风险分级 → 审批 → 执行 → 观察 → 反思 → 更新计划。

## 红线

- 破坏性动作默认禁止；生产数据只做「存在性证明」（截屏/计数/哈希摘要）不下载不外传；AI 自主利用必须受审批矩阵约束，可随时一键熔断。

## v4.6 S5 增补（投递纪律 + 对抗分型）

- 队列消费：impact-rank 升序 × **就绪度优先**——有就绪脚本的项先投递（签名/SM4/WASM oracle 立即转 CLI 投递器，每次投递响应原文落盘并回填 claims）；
- 对抗类目标先判 behavior_class 并 load_skill 对应 playbook；限速目标按 rate-limit-playbook 窗口化执行（单窗口 ≤6-10 请求，窗口间完全静默）；
- 浏览器通道动作前做 channel-snapshot（K1 强制）；批量动作遵守 js-challenge-waf-playbook 行为预算器。

## v4.6 W3 增补

- 投递纪律（crypto-offensive）：每次签名请求投递，请求/响应原文+双状态码（HTTP+json_code）落盘并回填 claims——杜绝「破解即终点」与无状态码探测；
- 鉴权矩阵 HIT 端点：同族复查→量化→record_finding（access/impact_rank 必标）。

## v4.7 增补（W7-lite 原语图 + K5 心跳）

- 阶段收口前对发现库跑原语链推荐：`python3 /opt/tools/primitive-graph.py --findings findings.json --out deliverables/primitive-chains.md`——已具备/缺口/下一动作三段式（正向扩展+反向回推），缺口项登记 VT（record_vt）；
- 阶段收口后若有预期空闲窗口（指挥室暂停/跨阶段间歇），用 run_async 调度通道心跳：`python3 /opt/tools/browser-kit/channel-heartbeat.py --url <登录页> --out evidence/channel-status.json --interval 600 --times 12`——S6 开工读 channel-status.json 即知通道状态。

## 执行模式契约（v5.3.1，与 loop-core 规则 6 / policies/execution-profiles.yaml 对齐）

- 本阶段默认 **production_safe**（未显式声明 isolated_lab 的项目一律按生产口径）：引擎在全部命令通道逐动作强制校验（v5.3.1 governanceGates）——植入/持久化/隧道/新增账号/上传可执行/批量导出/数据修改删除/订单支付短信状态变更直接拦截并留证，不要尝试绕行；
- 生产档内自建工件（落点/载荷/账号）处置：**登记移交**（《需人工清理清单》四元组），快照回滚不适用于生产；
- **isolated_lab**（客户专用隔离靶场且可快照恢复/环境重置）方可执行完整 PoC 链与受控写操作，收尾以**快照恢复/环境重置**回收（恢复成功须只读验证）；
- S5-3 落点登记口径不变：无论何档，四元组（路径/指纹/建议清理命令/验证命令）逐项登记。
