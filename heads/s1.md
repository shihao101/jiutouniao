# 阶段 1 · 资产与范围界定（SCOPING & ASSET INVENTORY）

**目标**：锁定边界内的「靶子」——尤其是最容易被遗漏的 AI 资产与影子资产。进入条件：授权书/ROE 已梳理。

## 分步动作

1. **S1-1 确认资产清单**：从项目上下文提取客户提供的资产（域名、IP 段、Web/APP、小程序、API、云账号），逐项 record_asset 登记；**范围状态必填（v6.1.0）**——授权清单内资产 `scope_status=in_scope` 并附 `scope_evidence`（如「项目授权清单」）；未核实线索一律 `shadow_pending`；需再授权标 `conditional`。缺失时以目标描述推导候选资产。APP/小程序/云账号/API 按类型化字段登记（APP：platform/store_url/package_id/version/backend_api；小程序：platform/app_id/version/backend_api/cloud_env_id；云账号：provider/tenant_id/role/region/authorization_ref；API：base_url/业务归属/认证方式类型）——**metadata 禁存明文凭据**，密钥只允许 `*_ref` 指针键；台账交付物表头同步这些字段（不适用填 N/A）。
2. **S1-2 AI 资产被动盘点（v6.1.0 拆分口径）**：从客户提供的清单、已获授权的公开文档及本阶段允许的被动公开来源识别 LLM 应用/聊天入口、Agent/插件、RAG/向量库、模型 API 与 MCP 入口；逐项登记资产类型、来源和范围状态。此步骤只识别与登记，不连接入口、不枚举模型接口、不提交提示或工具调用。专项 A 未启用时仍必须完成被动盘点；专项 A 的主动安全测试只在后续对应阶段且授权满足时执行。
3. **S1-3 明确边界内/外**：对照授权范围，把每个资产标注 in-scope / out-of-scope / 条件内（需再授权），形成《范围边界表》写入 `deliverables/s1-范围边界表.md`（逐资产含范围状态与判定依据——收口确定性门会核验该文件与逐目标归宿）。**范围边界表是后续所有阶段的合规依据。**
4. **S1-4 架构与信任边界草图**：基于已知信息绘制架构草图 V0（文字版），标注信任边界。
5. **S1-5 影子资产探测**：用只读命令查询证书透明度与公开 DNS 记录（如 `curl -s "https://crt.sh/?q=<域>&output=json"`、`dig`、`host`），发现清单之外的疑似资产；**只登记线索（scope_status=shadow_pending），不主动测试**，交人工核实归属。**执行形态（v6.3.1，S1 阶段门口径）**：查询逐条以单一只读命令执行、结果输出到 stdout；禁止 `>`/`>>` 重定向落盘、禁止 `bash`/`python3` 脚本包装与 `$()` 命令替换——脚本执行与重定向写按 L1 写操作被 S1 阶段门拦截留证；需留档的原始证据用 write_file 写入 `evidence/`（如 `evidence/s1-crtsh-<域>.json`、`evidence/s1-dns-records.txt`、`evidence/s1-whois-<域>.txt`），白名单内相对路径落盘参数亦放行（`curl -s <URL> -o evidence/x.json`、`dig … | tee evidence/x.txt`，落点=项目工作区沙箱）。
6. **S1-6 被动域名与网络归属清单（v6.1.0 必做）**：对每个授权根域记录 WHOIS/注册商/主体与隐私状态；逐项查 A、AAAA、CNAME、MX、NS、TXT、SOA、CAA；使用公开 ASN/网段与历史 IP/被动 DNS 来源补充关联线索。每条结果记录查询 UTC 时间、数据源、原始证据路径、目标资产、当前/历史属性及 scope_status。只查询公开数据源和 DNS，不对解析地址发 HTTP、端口或服务探测；无数据源/凭据时写明「未查询及原因」，不据此断言不存在。查询命令执行形态同 S1-5（逐条只读、stdout、write_file 落盘；禁止重定向与脚本包装）。

## 交付物

- 《资产台账（含 AI 资产标注与范围状态列）》《范围边界表》《架构草图 V0》《影子资产线索清单》。

## 红线

- **被动查询仅指向 CT、公开 DNS/WHOIS/ASN/被动 DNS 等数据源，不连接目标服务。任何发往目标的 HTTP 请求（包括单次 GET、httpx 存活/指纹）、端口探测和服务版本识别均属主动探测，S1 一律禁止**；仅在 S2、授权范围明确、ROE 时间窗和速率约束满足后执行。命令被全局 ClassifyRisk 归为 L0 不改变本阶段边界（引擎 s1 阶段门逐命令强制，违者拦截留证）。
- 影子资产必须由客户书面确认归属后才可测试（人工确认后用 update_asset 将状态流转为 in_scope 并附授权依据）；本阶段仅允许只读被动查询。
- 环境预热只做本地只读预检（command -v、已有模板/词表目录存在性），不安装工具、不下载模板、不启动服务（见宪法「阶段化环境预热」）。

## v4.6 S1 增补（K2 行为类分型）

- 承接时按目标历史与指纹**被动线索**（客户清单、历史项目黑板、公开测绘记录）预判 `behavior_class`（rate-limited / js-challenge-waf / closed-site / gateway-filter / appliance-mgmt / 普通），命中对抗类立即 load_skill 对应 playbook 并把类标写入黑板（`upsert_fact key=behavior.<目标>`）；不得为分型对目标发主动探测请求；
- 检索组织教训按 **behavior_class + stack** 检索（不按目标名——审计实证 某限速分型目标 的限速教训对同日 某限速分型目标 不可达）。

## v4.6 W2 增补（S1 子域线索，v6.1.0 收敛）

- CT/被动 DNS 候选解析后调用 **build_s1_subdomain_input**（S1 专用工具，纯本地零网络），生成 `evidence/s1-subs-final.txt` 与来源 manifest（`evidence/s1-subs-manifest.json`，无来源时记 not_checked）；对该文件执行仓库构建安装的子域接管 DNS 指纹脚本（`python3 /opt/tools/subdomain-takeover.py --subs evidence/s1-subs-final.txt`，纯 DNS 指纹，被动合法）。记录候选总数、完成数、未完成原因；只登记线索（shadow_pending）并交人工确认，**不做 HTTP 二次确认或接管**。S1 不抓取网站 bundle、JS chunk 或 source map（bundle 取件属 S3，见 s3 头 W2 节）。

## v5.4 S1 增补（OOB 通道核验·v6.1.0 收敛为管理员预置）

- OOB 通道由**管理员预置**（环境准备流程），S1 只核验不安装：核对 `evidence/oob/channel.txt`（最少字段：domain、pid、started_at_utc、self_check_id、self_check_result、channel_type、process_state）与 `evidence/oob/interactsh.log`、`evidence/oob/self-check.txt`；自检回连日志同目录留证——S4/S5 盲打类测试项直接消费该通道，禁止中途现装（盲打窗口时效性强，中途安装=损失回连窗口，实战实证多次）；
- 项目声明 `oob_required=true` 时，S1 收口确定性门核验上述产物（缺失/自检未通过=拦截）；通道不可用（工具缺失/无外联）时：登记移交并标注依赖 OOB 的测试项清单，兜底通道（自建 HTTP/NC 记录器）按 oob-interactsh 优先级链判定；
- 核验产物纳入 S1 交付物清单核对（S8 归档一致性）。**禁止把 /tmp 当唯一证据源**——进程日志可写 /tmp，但证据必须落 evidence/oob/。
