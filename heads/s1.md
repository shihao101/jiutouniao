# 阶段 1 · 资产与范围界定（SCOPING & ASSET INVENTORY）

**目标**：锁定边界内的「靶子」——尤其是最容易被遗漏的 AI 资产与影子资产。进入条件：授权书/ROE 已梳理。

## 分步动作

1. **S1-1 确认资产清单**：从项目上下文提取客户提供的资产（域名、IP 段、Web/APP、小程序、API、云账号），登记 record_asset；缺失时以目标描述推导候选资产。
2. **S1-2 AI 资产专项识别**：重点识别 LLM 应用与聊天入口、Agent 与插件/工具链、RAG 知识库与向量库、模型 API 端点、MCP 类接口；逐一登记为 AI 类资产。
3. **S1-3 明确边界内/外**：对照授权范围，把每个资产标注 in-scope / out-of-scope / 条件内（需再授权），形成《范围边界表》写入 `deliverables/s1-范围边界表.md`。**范围边界表是后续所有阶段的合规依据。**
4. **S1-4 架构与信任边界草图**：基于已知信息绘制架构草图 V0（文字版），标注信任边界。
5. **S1-5 影子资产探测**：用只读命令查询证书透明度与公开 DNS 记录（如 `curl -s "https://crt.sh/?q=<域>&output=json"`、`dig`、`host`），发现清单之外的疑似资产；**只登记线索，不主动测试**，交人工核实归属。

## 交付物

- 《资产台账（含 AI 资产标注）》《范围边界表》《架构草图 V0》《影子资产线索清单》。

## 红线

- 影子资产必须由客户书面确认归属后才可测试；本阶段仅允许只读查询（L0）。

## v4.6 S1 增补（K2 行为类分型）

- 承接时按目标历史与指纹预判 `behavior_class`（rate-limited / js-challenge-waf / closed-site / gateway-filter / appliance-mgmt / 普通），命中对抗类立即 load_skill 对应 playbook 并把类标写入黑板（`upsert_fact key=behavior.<目标>`）；
- 检索组织教训按 **behavior_class + stack** 检索（不按目标名——审计实证 某限速分型目标 的限速教训对同日 某限速分型目标 不可达）。

## v4.6 W2 增补（情报与 L0 火力）

- 子域线索解析完成后执行 `python3 /opt/tools/subdomain-takeover.py --subs evidence/s1-subs-final.txt`（纯 DNS 指纹，L0 合法），candidate 项登记移交（HTTP 二次确认需范围授权）；
- S3 的 bundle 取件按 load_skill intel-factory 强制清单执行（chunk 全量/运行时配置必取/sourcemap 还原→四件套）。

## v5.4 S1 增补（OOB 通道预热·盲打窗口前移）

- OOB 通道预热从「用到才装」前移到 S1 工具自检：按 load_skill oob-interactsh「通道自检」完成本机通道注册，回连域/PID/起服时间落盘 `evidence/oob/channel.txt`，自检回连日志同目录留证——S4/S5 盲打类测试项直接消费该通道，禁止中途现装（盲打窗口时效性强，中途安装=损失回连窗口，实战实证多次）；
- 通道不可用（工具缺失/无外联）时：登记移交并标注依赖 OOB 的测试项清单，兜底通道（自建 HTTP/NC 记录器）按 oob-interactsh 优先级链判定；
- 自检产物纳入 S1 交付物清单核对（S8 归档一致性）。
