# 专项 A · AI（LLM/Agent）目标系统渗透测试（A1-A14）

**适用**：聊天应用 / Agent / 模型 API / RAG 系统——**v5.9.0 编排裁决（混合模式）**：specA 是 s4/s5 的**专项扩展层**而非替换——s4 的通用骨架（匿名面/身份获取六轨/覆盖矩阵/收口门）与 s5 的利用/影响证明对 LLM 目标仍是必要前置，specA 的 A1-A14 专项清单在其上叠加执行（与 Pipeline 追加语义一致）；A1-A14 命中项按通用口径 record_finding/update_coverage 汇入主流程。**与 S3 的编号契约（v6.3.0）**：s3 威胁建模对 AI 资产的 LLM Top 10 映射与本研究同源——s3 按 2026 版编号挂接威胁清单 TH，判定表 AI 资产行标注 `AI:specA`（hypothesis-matrix 头部声明），本专项 A1-A14 消费时无需二次翻译。
**框架（v6.0.2 重基线，据 docs/调研报告_三大专项_20261120.md）**：OWASP LLM Top 10 (2026) · OWASP Agentic Applications Top 10 (2026) · MITRE ATLAS（数据版本 2026.10 / 格式 6.1.0）。右侧 2026 版映射：LLM01 提示注入、LLM02 敏感信息泄露、LLM03 过度代理、LLM04 供应链、LLM05 数据与模型投毒、LLM06 无限制资源消耗、LLM07 误导信息、LLM08 隐藏上下文暴露、LLM09 向量与嵌入弱点、LLM10 输出处理不当。**2025 旧编号交叉表保留（历史报告可比性）**：LLM05 输出处理不当→2026 LLM10、LLM06 过度代理→LLM03、LLM10 无限制资源消耗→LLM06、LLM07 系统提示泄露→扩展为 LLM08 隐藏上下文暴露（覆盖系统指令、隐藏上下文及实现细节）；名次基于事件与从业者判断，不作单目标风险排序。Agentic Top 10 (2026)：Agent 目标劫持 / 工具滥用 / 身份与权限滥用 / 供应链 / 意外代码执行 / 记忆与上下文投毒 / 不安全 Agent 间通信 / 级联失效 / 人机信任滥用 / 流氓 Agent。测试计划与证据组织可参照 NIST AI RMF/GenAI Profile（MEASURE 2.5/2.10、MANAGE 1.3）与 NIST ARIA 规划手册；ISO/IEC 42001 仅用于治理证据，不作为漏洞分类。

## 前置契约（v5.3.0，production_safe 强制）

AI 专项验证器依赖：客户放置的 Canary 标记、mock 邮件/支付/文件工具、隔离测试租户与合成 RAG 文档。真实秘密/真实用户数据不是验证目标；仅观测到未经授权的真实工具副作用或跨租户 Canary 泄露才确证影响（A1-A14 同此口径）。

**开工承接（v6.6.0 SP-⑦）**：先消费上下文「S4 AI 面移交」块——S4-5 已排查登记的 AI 面发现与 AI 类资产直接复用，不重复面测；块内 shadow_pending/非 in_scope 资产**不得发起主动测试**（登记≠授权）；「S3 判定表 AI:specA 承接行」即威胁建模移交的 AI 面假设，逐行纳入 A1-A14 条目对账。

## 流程语义（v6.6.0 SP-⑩）

- **早退分支**：开工先核验资产台账——项目无 AI/LLM/Agent 类资产（record_asset type 含 ai/llm/模型/agent）时，按「前提不成立」如实收口（交付物写明豁免依据并引用台账核验结果），**禁止虚构测试动作**；引擎收口门对该形态走豁免路径。
- **回环语义**：本阶段不会被下游阶段回环自动连带（spec 为并列专项非下游）——上游 s4/s5 回环补跑产生**新 AI 资产/新 AI 攻击面**时，显式 `loopback(to_stage=specA)` 触发本专项补测，或提请人工在「阶段流水线」重跑；都不适用时 record_vt 移交（三选一留痕，禁止静默滞留）。

## 分步动作

1. **A1 AI 资产与架构测绘**：模型来源（自研/开源/闭源 API）、RAG/Agent/插件拓扑、防护层（内容安全/WAF/注入检测）、网关与身份层、数据流；**增加 Agent 间委托关系与会话上下文边界的测绘**；产出《AI 系统架构图》《组件与信任边界清单》。
2. **A2 行为基线构建**：设计正常问答集与边界问题集，记录基线响应，供后续对比判定攻击是否成功；**基线快照纳入模型/提示模板版本、工具描述、策略配置与网关版本**；产出《基线响应集》《模型指纹》。
3. **A3 系统提示与隐藏上下文提取（LLM08；2025 版编号 LLM07）**：直接诱导、分段套取、要求总结/翻译/编码输出等手段套出系统提示、隐藏上下文与实现细节；**记录口径（v5.8.0 与前置契约统一）：命中判定用合成 Canary（对照实验），成功提取的片段只记《泄露要点摘要》（截取 ≤200 字符的关键约束/角色/边界句 + 完整性分级 + 敏感性分级），不落系统提示原文**（与 mock/Canary 约束一致；原文留在证据文件且仅授权靶场环境）。《策略绕过点》照记。
4. **A4 提示注入（直接/间接）（LLM01）**：直接注入用户输入；间接注入**显式覆盖检索内容、工具返回、持久记忆与跨轮/跨会话传播路径**（多模态通道见 A6a）；**验证重点是注入对后续授权与工具行为的实际影响，不以模型复述恶意内容为成功判据**；记录《注入成功载荷与路径》《危害等级》。
5. **A5 越狱与安全策略绕过**：角色扮演、多轮升级、多语言、编码变形、模板越狱，绕过内容安全与业务约束；**判定同 A4——以策略/授权实际失效为准**；记录《越狱样本》。
6. **A6 敏感信息泄露（LLM02/08/09 + ATLAS 训练数据/模型内部条目）**：PII 与内部数据泄露、RAG 越权检索、多租户隔离、训练数据成员推断；**区分跨租户、检索边界、训练数据记忆与模型抽取四类风险**；使用合成标记数据验证，不收集真实用户数据。
7. **A7 Agent 与工具滥用（LLM03 过度代理；对应 Agentic Top10 ASI-02/03/05/07/08/09/10 等）**：过度代理、工具参数注入、间接注入驱动工具调用（发邮件/写库/SSRF）、权限链分析；**核查工具身份、委托权限、参数展示、调用授权、工具返回可信度、错误传播与人工审批——不只验证调用参数能否被模型控制**；记录《工具滥用证明》《可达权限清单》。
8. **A8 输出处理链攻击（LLM10；2025 版编号 LLM05）**：模型输出进入下游执行：XSS / Markdown 注入 / SQL / 命令执行 / SSRF / URL / 代码解释器，**验证下游消费者安全编码与沙箱边界**（2026 版名次调整不改变验证必要性）；记录《下游利用证明》。
8a. **A6a 多模态注入**：图片/PDF/音频携带提示指令（OCR/视觉/转录通道进入上下文的路径），构造含无害指令的测试文档投递验证；**覆盖图片/音频中的隐藏与非显著指令、OCR/转录链与多模态工具结果的来源追踪**；结论按 A4 同等纪律入库。
8b. **A7a Function calling 滥用**：枚举模型可调用工具清单（诱导自述+文档），测试参数注入、越权工具调用、工具参数中的二次注入（工具调用目标系统）；**扩展核查工具返回内容作为注入源的可信度处理与错误传播路径**。
9. **A9 资源与可用性（LLM06；2025 版编号 LLM10）**：无限制消耗（超长对话/大文件/批量请求）造成成本与可用性风险；**对齐 Agent 循环与 ATLAS 资源消耗类条目，在批准额度内观察重试、并行工具链、上下文膨胀、第三方模型计费与熔断行为**；**只做小规模受控验证并立即停止**。
10. **A10 供应链与模型层（LLM04/05）**：模型与插件来源、依赖 SDK、微调数据源审查；**扩展 Agent 工具目录与 MCP Server 供应链——版本锁定、来源校验、工具定义变更监测、学习环境投毒检查**；模型窃取/对抗样本仅在条件允许且获批时。
11. **A11 防护有效性验证（收口）**：对注入检测、输出过滤、速率限制逐项复测，确认防护真实生效或给出绕过证明；**验证范围从单轮提示过滤扩展到系统提示/上下文、工具 schema 与结果、出站连接、网关策略、遥测告警与策略变更；采用自适应/黑盒/多轮方式；记录防护产品版本、策略配置与误报/漏报边界**；结论需人工确认，避免模型误判。
12. **A12 Agent 协议与委托信任边界（v6.0.2 新增）**：对 MCP、A2A 等协议检查身份验证、令牌受众与委托、能力/工具定义变更、上下文来源、消息完整性与出站路径；**记录服务端与客户端实际实现的协议规范版本**（MCP 2026-07-28 起 OAuth 受众绑定/令牌不透传/混淆代理/工具描述与实现被替换/过宽权限/SSRF/工具结果诱导均为核查点）；验证结果限于测试 Agent 和测试工具。
13. **A13 Agent 记忆与目标完整性（v6.0.2 新增）**：检查短期/长期记忆、检索语料、会话恢复与跨任务共享的写入者、保留期、隔离及删除控制；**确认低可信内容不能持久改变后续授权行为**。
14. **A14 LLM 网关与策略链（v6.0.2 新增）**：识别模型代理、内容安全、防火墙、缓存、日志与路由层，分别验证输入/检索/工具结果/输出各经过哪些控制及失败时行为；**记录审计与版本证据**（不同产品检测层位置与覆盖不一致——如部分网关的 prompt attack 检测不分析工具结果或工具定义，逐层核对输入覆盖与放行/阻断决策）。

- 核心交付物写入 `deliverables/`：《AI 系统架构图》《基线响应集》《注入成功载荷与路径》等按步骤产出；收口交付物须含《专项条目清单》（A1-A14 逐条三态：已测（update_coverage 引用）/ 不适用（依据）/ 未测（原因+移交去向））。

## 收口确定性门（v6.6.0 SP-②）

- **开工即登记前置契约**（引擎收口门核验留痕，缺失拦截）：①Canary/合成标记数据方案（验证器依赖——生产档只做存在性证明，Canary 对照实验是命中判定前提）；②测试租户/测试身份状态。
- **收口确定性门三件**（complete_stage 时引擎机械核验，与 S1 四件套门同机制）：①前置契约登记留痕（时间线/交付物任一）；②核心交付物存在（**《AI 系统架构图》或《基线响应集》**其一）；③《专项条目清单》存在（A1-A14 逐条三态：已测/不适用/未测——引擎本门只查清单存在，三态完整性与逐条判据由反思门按清单抽查）。资产台账无 AI/LLM 类资产时走豁免（前提不成立如实收口，禁止虚构测试）。
- **V3 双清单（v6.6.0 SP-③，引擎强制）**：收口提交 `ready_but_unexecuted`（就绪未投递的用例/oracle/PoC——每条附就绪资产路径与启动条件）与 `l2_approved_unused`（已批未用 L2 工单），无内容传空数组 []；S5 开工经「专项就绪移交」块承接，禁止静默蒸发。
- **反思门专项核查（v6.6.0 SP-⑧）**：反思门会对本阶段按清单专项核查——①候选验证是否配齐正/负/基线对照（缺正对照不得「确证」，Canary/mock 前置契约兑现）；②「注入成功」是否以对后续授权与工具行为的实际影响为准（模型复述恶意内容不算）；③系统提示/隐藏上下文原文是否落库（违反 A3 ≤200 字摘要口径即 BLOCK）。被拦截需按意见修正后重提。
