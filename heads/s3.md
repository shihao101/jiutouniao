# 阶段 3 · 威胁建模与测试计划（THREAT MODELING & PLANNING）

**目标**：从「有什么资产」推进到「打哪里、怎么打、按什么顺序打」。

## 分步动作

1. **S3-1 绘制数据流图 DFD**：按外部实体/进程/数据存储/数据流四要素整理系统组件，标注信任边界；结合架构草图生成初稿，**并以 `deliverables/拓扑重建-V1.md`（S2-11 产物）为 DFD 校准输入**——文件存在时逐组件核对响应头指纹/错误页特征/JS 内网引用/多端口差分四源证据；缺失时在威胁模型记「S2 未产出拓扑重建」并说明原因。
2. **S3-2 威胁枚举与映射**：传统资产按 STRIDE 逐元素枚举；AI 资产逐条对照 OWASP LLM Top 10（**2026 版口径**，编号映射与 2025 交叉表见 heads/specA.md：LLM01 提示注入、LLM02 敏感信息泄露、LLM03 过度代理、LLM04 供应链、LLM05 数据与模型投毒、LLM06 无限制资源消耗、LLM07 误导信息、LLM08 隐藏上下文暴露、LLM09 向量与嵌入弱点、LLM10 输出处理不当）与 MITRE ATLAS 战术。产出《威胁清单（含映射编号，编号以 2026 版为准，禁用旧序）》。
3. **S3-3 攻击树与路径推演**：以业务目标（如「获取管理员数据」）为根反向分解前置条件，形成攻击树；推荐最短路径假设。
4. **S3-4 风险排序**：可能性 × 影响打分，叠加业务权重，得到优先级测试项列表；**可能性（L1 被动线索/L2 匿名可达/L3 需身份）× 影响（I1 存在性证明/I2 数据可见/I3 可执行接管）→ P1-P4 优先级刻度**（刻度表与 P1-P4→S8 定级映射见 hypothesis-matrix 第六节），威胁清单每条 TH 标注等级，S8 报告定级据此回溯。
5. **S3-5 测试计划细化**：每项测试明确：手段、工具、AI 角色、预期输出、审批点、回滚方案、时间窗。产出《详细测试计划（含 AI 任务分解）》写入 `deliverables/s3-测试计划.md`。**计划须含端点表产出条目（v6.4.0 S4-②）**：evidence/s3-api-endpoints.txt（intel-factory 四件套之一，S4 authz-diff 全量硬门的直接输入）列为计划必产项；确无 API 面时计划写显式声明行「未产出端点表：<原因>」——二者缺一收口门拦截。
6. **S3-6 已知漏洞对照层（必做）**：合并 S2-8 候选清单（固定读 `deliverables/s2-已知漏洞候选清单.md`；**该文件存在时计划必须含《已知漏洞测试项》对照层；缺失时在计划中写显式声明行「S2 未产出候选清单」+原因——两种形态缺一会被 s3 收口门拦截**，不得凭记忆虚构 CVE），按「组件×版本→CVE→验证难度→影响」生成《已知漏洞测试项》，直接编入测试计划优先级队列（实战命中率最高项优先排期）；计划条目统一编号（T-xx）——**T-xx 由 s4 开工逐类对账表逐条承接（s4.md v6.0.5），未承接条目收口前须显式归宿（执行/移交/作废附理由）**。
7. **S3-7 审批预请求（必做）**：计划中识别出的 L2 级动作（利用验证/写操作/横向/OOB 外带注册/隧道握手等）**在本阶段立即用 request_approval 发起审批工单**，不等 S5 才申请——实测教训：审批与预算竞态（审批未发、预算先尽，高危项因此流产）；工单留痕（状态由引擎在 S4/S5 上下文注入「审批工单状态」块，S5 开工逐单核对），S5 开工时确认关键审批已就绪或已拒。
8. **S3-8 陌生环境深挖计划（0day 能力项）**：计划必须含「陌生环境五轨深挖」排期（隐藏参数发现 / 响应差异 fuzz / JS 与文档泄露承接 / 二阶存储路径 / 逻辑滥用，见 loop-core 深度测试纪律 9）——**工作区存在 `checklist.json`（S2-9 目标自述面清单）时必须 read_file 逐条读取并排期**（只排为覆盖下限，无法排期条目显式标 deferred 附理由；计划零引用该清单会被 s3 收口门拦截），**清单外盲挖排为独立测试项**；产出计划中显式列出「清单外发现」的预期产出与判分口径。
9. **S3-9 筛查矩阵判定（v4.8 必做，M2 门机械校验）**：load_skill hypothesis-matrix（K3 假设模式库）载入 27 类筛查矩阵，基于 S1/S2 既有证据对 **27 类逐类三态判定**（`假设`/`不适用`/`待判定`，判定基于既有证据推理，**零新增主动流量**）：①目标存在对应攻击面 → `假设` 附证据指针；②无对应面 → `不适用` 附核查证据（不许空口判定）；③语义未知 → `待判定` **双假设并列**（如取件参数位：穿越 OR SSRF）并写明 s4 裁决手段。产出《筛查矩阵判定表》写入 `deliverables/s3-筛查矩阵判定表.md`（行格式规范见技能：首列 `C-01..C-27`，判定列恰为三态之一，27 行缺一不可——引擎 M2 门按行机械校验）。**v6.3.0 执行卡（判定=假设 或 待判定 的行必须附——待判定是 s4 双假设裁决投递单元，与引擎 M2 门口径一致）**：每条假设一行式执行卡——`入口定位（URL/参数位）→ 首个探针（具体请求模板）→ 阳性信号 → 阴性信号 → 停止阈值（默认 ≤6 请求/候选，对齐 loop-core 11）`——s4 按执行卡直接投递，不再从零推理。**多目标项目判定行落到目标粒度**（行格式与合并规则见 hypothesis-matrix 第三节：`C-xx | 目标 | 触发面 | 判定 | 证据 | TH/卡`，同判定同证据可合并多目标为一行；每个目标的每个假设/待判定类都必须有显式行，不适用可一行全目标声明；**单目标项目使用 6 列格式时第 2 列必须写目标名，触发面/摘要不得占用目标列**——v6.4.0 消歧，C27 对单目标按项目级键对账）。行业目标先 load_skill industry-templates（K1）做优先级升格与数据类具象（C-17）；框架指纹先验 load_skill framework-priors（K2）。判定出的假设并入 s3-4 优先级队列与威胁清单（TH 编号挂接）。
10. **S3-10 假设缺漏审查（v4.8 R7 第一层，收口前必做）**：按 hypothesis-matrix 第五节《假设缺漏审查+风险审计》结构化清单逐项自审并留痕入交付物：①筛查矩阵 27 类三态完整性 ②STRIDE 逐组件完备性 ③组合链覆盖（防护绕过→同构面复用）④数据类映射 ⑤影响等级一致性。反思门会按清单抽查；引擎 M5 统计反思门失败率，持续高失败会注入修复提示。

## 交付物

- 《威胁模型（DFD + 威胁清单，TH 编号）》写入 `deliverables/s3-威胁模型.md`（引用拓扑重建校准，TH 条目带 L×I 等级）；《攻击树》《优先级测试项列表》并入威胁模型或独立落盘；《详细测试计划（含审批点、T-xx 编号）》写入 `deliverables/s3-测试计划.md`（含 CVE 对照层或「S2 未产出候选清单」声明）；《筛查矩阵判定表（三态 + 执行卡，C-01..C-27）》写入 `deliverables/s3-筛查矩阵判定表.md`（引擎 M2 门机械校验）；《假设缺漏审查留痕》。**端点表生产端契约（v6.4.0 S4-②）**：`evidence/s3-api-endpoints.txt`（/ 前缀路径+参数名，表尾 `# total=N` 注记——S4 authz-diff 全量覆盖率硬门与端点表↔矩阵门的唯一结构化输入）必须产出；确无 API 面（纯内网/纯静态）时在测试计划写明显式声明行「未产出端点表：<原因>」——二者缺一引擎收口门拦截。

## 注意

- AI 生成的威胁模型可能存在幻觉与漏项：全部结论标注置信度，计划须经人工复核后方可作为后续阶段依据（在 complete_stage 摘要中请求人工确认）。

## v4.6 W2 增补（S3 bundle 情报，v6.1.0 承接归属）

- 仅在 S2 已确认授权的目标（scope_status=in_scope）和 ROE 条件满足后执行 bundle/JS/source map 取件；加载 intel-factory 清单（四件套：端点表/密钥材料/业务状态机/内网拓扑——端点表是 S4 Authz-Diff 的直接输入），保存来源 URL、响应状态与原始证据；运行时配置文件必取（主 bundle 计数 0≠无线索）。S1 的候选或未确认资产（shadow_pending/conditional）不得作为下载目标。

## v7.3.0 C1 增补（红蓝对抗环 + 可证伪假设卡）

- **红蓝对抗环（引擎自动化，替代旧一次性 R7）**：s3 收口时引擎自动执行 2 轮红方迭代——R1 独立红队视角复查攻击面；R2 携带 R1 假设清单**专攻双方都未覆盖的角度**。差异项与主清单 diff 后自动入验证队列：**证据指针可核存的直接 status=ready**（不再等确认），「纯推测」保持 pending 防噪声；每轮独立交付物（s3-对抗假设审查.md / -R2.md）留痕。
- **可证伪假设卡（判定表执行卡两格升级）**：每条「假设/待判定」行的执行卡必须含两格——`机制假设`（为什么这里可能有洞，引用具体证据 ID/事实键，禁止空想）+ `证伪条件`（什么观测结果说明假设错了，即 hypothesis-0day 的阴性信号具象化）。反思门按此抽查；无证伪条件的执行卡=未完成判定。
