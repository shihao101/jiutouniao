# 专项 B2 · AI 针对小程序的渗透测试（W1-W10）

**适用**：微信（wxapkg）/支付宝/抖音等小程序。AI Agent 全程驱动：解包还原 → 配置与密钥审计 → 前端逻辑推理 → 接口与云侧利用；所有结论汇入主流程阶段 5-8。**v6.0.2 按 docs/调研报告_三大专项_20261120.md 重基线。**

## 前置契约（v5.3.0）

登记小程序包来源、解包产物、签名/加密 oracle、API 端点清单与测试身份状态。接口请求仅落测试租户/合成数据；无测试租户时支付/订单/跨用户测试移交（needs_follow_up），不执行真实业务写操作。**ROE 边界区分目标小程序/自有后端、云服务租户与平台本身——微信/支付宝/抖音平台基础设施及其他租户不因目标授权自动纳入范围；合规/备案发现与技术漏洞分开定性。**

## 流程语义（v6.6.0 SP-⑩）

- **早退分支**：开工先核验资产台账——项目无小程序类资产（record_asset type 含 小程序/miniapp）时，按「前提不成立」如实收口（交付物写明豁免依据），**禁止虚构测试动作**；引擎收口门对该形态走豁免路径。
- **回环语义**：本阶段不会被下游阶段回环自动连带（spec 为并列专项非下游）——上游回环产生**新小程序包/新云侧线索**时，显式 `loopback(to_stage=specB2)` 或提请人工重跑；都不适用时 record_vt 移交（三选一留痕）。

## 分步动作

1. **W1 包获取与结构还原**：经授权渠道获取小程序包；**wxappUnpacker/unveilr 均已停更——不再作为唯一工具或可分发基线；用多个经审查的可维护实现（活跃 fork、Gwxapkg、wxapkg 桌面工具等）交叉确认，固定工具来源与哈希**；还原页面树、组件关系与 app.js 全局逻辑；产出《小程序结构与页面清单》；**环境内置双实现交叉（v6.6.0 SP-⑨）**：wxappUnpacker 主 + Gwxapkg 备（来源与 sha256 见 /opt/tools/wxapkg-implementations.txt），关键结论双实现交叉确认、不一致逐包记录差异，命令骨架见 load_skill miniapp-audit；**记录平台、包型、加密状态、主包/子包覆盖率、来源哈希与解析失败项——公开资料无稳定权威的 wxapkg 版本规范，不假定所有包格式相同，不以「成功解包」描述为完整源码恢复**。
2. **W2 配置与密钥审计**：扫描 AppID / AppSecret / 云开发 envId 泄露、request 合法域名与接口鉴权方式、调试接口与 source map 残留；**扩展第三方服务凭据、云凭据、OAuth 配置、服务端密钥使用位置与开发/生产环境隔离——AppID 通常不是秘密，仅在具备权限影响时把暴露配置认定为漏洞**。
3. **W3 AI 前端逻辑审计**：语义分析前端判断逻辑：会员/优惠券/抽奖条件、支付金额前端可控点、隐藏页面与入口；生成绕过场景假设；**增加宿主 API/平台权限 API 与桥接调用链观察**（深入项见 W8）。
4. **W4 接口与鉴权测试**：复用签名逻辑构造请求：未授权访问、水平/垂直越权、ID 遍历、token 刷新缺陷（严格限频、仅测试账号）；比对响应差异判定漏洞成立；**加入平台登录授权码交换、身份绑定、会话创建/刷新与一次性/重放控制**（深入项见 W7）。
5. **W5 云开发与后端测试**：云函数未授权调用与参数注入、云数据库 security rules 越权读写、云存储遍历；判定可利用性与影响面；**分清客户端安全规则与云函数/服务端 SDK/管理面权限——规则配置通过不代表云函数自动受保护；覆盖触发来源、HTTP 入口、IAM、对象存储、开发/生产环境与服务器端业务授权**（深入项见 W9）。
6. **W6 证据固定与汇入主流程**：整理 PoC/抓包证据汇入主流程阶段 5-8 出报告；复测时验证前端热修复与接口防护真实生效；**隐私/备案/平台政策发现独立分类，写明授权边界说明**（深入项见 W10）。
7. **W7 平台登录态与身份绑定（v6.0.2 新增）**：测试登录授权码生命周期、服务端换取会话、用户身份与资源所有权映射、令牌刷新/撤销及防重放；**不访问真实用户账号**。
8. **W8 宿主能力与跨小程序隔离（v6.0.2 新增）**：评估宿主桥接、敏感权限 API、WebView/页面来源、Cookie/会话共享及跨小程序数据边界，确认平台 API 的授权检查和错误处理。
9. **W9 云资源身份与部署边界（v6.0.2 新增）**：盘点云函数调用来源、HTTP 暴露、服务身份/IAM、数据库规则、对象存储及开发/生产配置差异；**使用无敏感数据的受控对象证明访问控制结论**。
10. **W10 备案、隐私披露与 SDK 治理证据（v6.0.2 新增）**：将备案主体/标识、权限说明、隐私政策、SDK 收集与数据删除路径作为独立治理检查项，**与技术漏洞分开定性**；核验隐私接口调用前的授权状态、提审声明与运行行为一致性。

## AI 与工具分工

- 解包：多个可维护实现交叉确认（活跃 fork / Gwxapkg 等，固定来源与哈希，记录覆盖率）；mitmproxy 抓包；LLM 审计代码与业务逻辑、生成绕过假设；Agent 复用签名逻辑自动构造请求；Node 沙箱复现前端判断逻辑。

## 交付物与多目标分组（v6.6.0 SP-①）

- 核心交付物写入 `deliverables/`：《小程序结构与页面清单》《配置与密钥审计》《接口与云侧测试记录》等按步骤产出；收口交付物须含《专项条目清单》（W1-W10 逐条三态：已测（update_coverage 引用）/ 不适用（依据）/ 未测（原因+移交去向））。
- **多目标分组产出约定（v6.6.0 SP-①，与 s4.md S4-9 同族口径）**：按目标组（每个小程序）推进时每组结论写 `deliverables/specB2-<目标或组名>.md`（含该组解包覆盖率、接口与云侧结论与待续项），S8 报告承接合并；收口前逐组核对 update_coverage 已登记——引擎专项逐目标对账门按目标归宿拦截（与 S4-9/S5 同口径）。

## 收口确定性门（v6.6.0 SP-②）

- **开工即登记前置契约**（引擎收口门核验留痕，缺失拦截）：①小程序包来源与解包产物登记；②测试身份状态（测试账号/测试租户）。
- **收口确定性门三件**（complete_stage 时引擎机械核验）：①前置契约两要素登记留痕；②核心交付物存在（**《小程序结构与页面清单》或接口测试记录**其一）；③《专项条目清单》存在（W1-W10 逐条三态——引擎只查清单存在，完整性由反思门抽查）。无测试租户时支付/订单/跨用户测试按前置契约移交（needs_follow_up），不执行真实业务写操作。资产台账无小程序类资产时走豁免（前提不成立如实收口）。
- **V3 双清单（v6.6.0 SP-③，引擎强制）**：收口提交 `ready_but_unexecuted`（就绪未投递的签名 oracle/请求构造器/PoC——每条附就绪资产路径与启动条件）与 `l2_approved_unused`（无内容传空数组 []）；S5 开工经「专项就绪移交」块承接，禁止静默蒸发。
- **反思门专项核查（v6.6.0 SP-⑧）**：反思门会对本阶段按清单专项核查——①测试是否越出平台边界（平台基础设施与其他租户不因目标授权自动入范围）；②支付/真实用户数据操作是否全部经审批；③解包子包覆盖率与解析失败项是否如实记录（不以「成功解包」描述为完整源码恢复）。被拦截需按意见修正后重提。

## 红线

- 只用测试账号与测试环境；**涉及支付、真实用户数据的操作先审批**；解包产物仅用于授权测试、禁止分发；小程序内嵌 AI 功能时叠加专项 A；**平台自身审查/基础设施及其他租户排除在目标授权之外，不利用平台漏洞或绕过平台机制**。
