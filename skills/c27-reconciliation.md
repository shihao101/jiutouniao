## 二、处置态定义（每行必须含其一，引擎按行正则核验）

| 处置态 | 何时用 | 行内必备 |
|---|---|---|
| **已测** | 该类有实际测试单元（含 S4/S5 已投递、S6 增量） | 测试单元描述 + 证据指针（evidence/ 路径或 F-/VT- 编号） |
| **合规豁免** | 无凭据（no_credentials）/ 生产档写禁（production_safe_write_prohibited）/ 前提不成立类豁免 + 依据 | 豁免枚举词 + 一句话依据 |
| **环境不可达** | 目标后端/网络不可达（502/超时/封闭） | 原因 + 移交编号（VT 或 待续清单指针） |
| **待续** | 有信号但本轮预算/前提不足，deferred | `待续` 或 `deferred` + VT 编号与启动条件 |

- 引擎判别正则按行首 `| C-xx` 提取类编号，同行必须出现处置词（已测/已投递/不适用/待续/deferred/no_credentials/production_safe_write_prohibited/环境不可达/合规豁免）——**缺处置词的行按缺失拦**。
- 反例：`| C-02 | … |（待补） |`（无处置词）= 无效行；「已测」无证据指针 = 反思门按 S6-⑤ 节拦截。

## 三、多目标项目（类×目标 复合键，guard enforce_target_class_matrix）

- 判定表按目标拆键的假设/待判定组合，在对账表**逐组合处置**——标准 6 列格式（`C-xx | 目标 | 触发面 | 判定 | 证据 | TH/卡`），类编号与目标在同一条留痕内同现。
- 5 列项目级行（无目标列）覆盖该类的全部复合键与项目级键——同判定同证据可合并一行，但**前提是该类判定对所有目标同态**；否则逐目标分行。
- 单目标项目：项目级行即覆盖（6 列/5 列行均按类归账，行为不变）。

## 五、执行纪律

1. 开工即建表骨架（27 行占位），随测试推进逐行回填——不要收口时一次性凭记忆编造（无证据指针的「已测」行反思门按 S6-⑤ 拦）。
2. 与 S5→S6 承接提示联动：S5 V3 清单条目按价值消费后，在对应 C 行的「测试单元与结论」列标注「S6 增量」。
3. 表是 S8 报告的直接承接件——S8 按「已测/豁免/不可达/待续」统计安全向量与盲区两章，不在报告里重建。
