# 无凭证身份获取路线图（先查我：任何"需要登录才能测"的项开工前）

> 定位：无凭证项目的第一优先动作不是按漏洞类扫描，而是**把身份问题变成一个可攻击的漏洞类**。
> 每条路径都标注：成本（轮次）× 合规边界 × 成功判据。命中任何一条即转 session-state-chain
> 建会话，然后回到标准流程。禁止在未走路线图前对认证后功能下"放弃测试"结论。

## 零、路线决策树（按成本升序尝试）

L1 注册面（最常见、最合法）→ L2 泄露面 → L3 默认/弱口令 → L4 逻辑与验证码缺陷 → L5 令牌伪造 → L6 会话构造

## 一、L1 注册与开通面（v5.1：评估轨——只评估不注册，ROE 门控）

> **政策（v5.1）**：注册面默认只做**评估**不执行——在客户生产系统自动创建账号会留下持久数据
> （账号/激活邮件/审计日志）、可能触发真实业务流，且注册账号后续操作在客户侧审计中归属模糊。
> ROE `identity.auto_register: deny`（默认）时禁止执行注册；`allow`（客户书面授权）才可按
> 原流程执行并全量登记 S7 清理。评估产出照常入账：**"开放自助注册"本身就是一个发现**。

1. **开放注册探测（评估态）**：/register /signup /api/v1/user/register 入口存在性、
   注册流程协议还原（端点/参数/验证码类型/激活流——静态还原零投递，intel-factory 口径）；
   APP/小程序同测（specB1/B2 联动）。deny 模式下到此为止，注册接口的 mass assignment
   探测转 record_vt（需身份后或 ROE allow 时执行）。
2. **注册接口的 mass assignment**（仅 ROE allow 执行）：注册/资料更新请求体追加 role=admin /
   isAdmin=true / status=active / parentId 等敏感字段（load_skill injection-points JSON 层级遍历）；
   判据=注册响应或首次登录后的权限行为变化。
3. **注册即低权**（仅 ROE allow 执行）：注册成功的"最低权账号"立即作为 S4-2 认证前置类的钥匙，
   登记 loot 并入 S7 清单——**v5.1.3：账号只登记移交、不执行清理/注销删除**。
4. **邀请码/企业开通流**（评估态可探测存在性；绕过验证的实测需 ROE）：邀请码可枚举
   （短数字/日期/自增）、试用开通绕过邮箱验证（响应含激活链接/验证码回显）——命中即
   record_finding（认证绕过类）。

## 一a、身份索取闭环（v5.1：自建账号被禁后的标准动作）

六轨全部走完（或 L1 被 ROE 关闭且其余轨未命中）仍无身份时，**禁止静默放弃认证后测试**：

1. `request_user_input` 向客户**索要测试账号**（标准口径：按角色提供低权+高权两个账号、
   测试资金额度、可用的测试邮箱/手机）；
2. 客户提供 → load_skill session-state-chain 建会话，认证后项转有身份流程；
3. 客户拒绝/超时 → 认证后项统一 needs_follow_up 移交，S4 收口三行报告与 S8 报告
   「盲区」章**明确写明"因 ROE 禁止自建账号且客户未提供测试账号"**（移交链完整，责任清晰）。

## 二、L2 泄露面（S2-7 成果承接）

1. **JS/source map 硬编码**：AK/SK 前缀特征（LTAI/AKID/ghp_/sk-）、内网域名、加密密钥
   常量；逐个核对可达性（键存在≠可用，需带 key 的无害 API 调用判据）。
2. **.git/CI 配置/网盘文档**（devops-exposed 承接）：数据库连接串、SMTP 凭据、云 AK——
   只证明存在性（登录失败/成功一次即停）。
3. **Swagger/knife4j 文档面**（api-doc-leak 承接）：文档标注"需管理员"的接口先按匿名直调
   探测（401/403 差异），未授权即高危发现。
4. **泄露凭据口径**：S2-4 命中的邮箱-口令对，仅对授权范围内登录口做**单次**验证（不撞库）。

## 三、L3 默认/弱口令（weak-cred-bruteforce 全文承接）

- 本路线图只强调排序：**先查默认凭据矩阵（查表），后爆破（受控）**；
  后台/运维面板入口优先于前台用户口（前台常有锁定策略，后台常无）。

## 四、L4 验证码与注册逻辑缺陷（一线 SRC 实战系）

1. **验证码回显**：注册/登录/找回响应体搜 code/captcha 字段；短信下发接口响应、
   通用错误码差异。判据=响应中拿到可用的 4-6 位码。
2. **验证码可控/可复用**：code 置空/000000/123456；同码多次提交；跨接口复用
   （注册码找回用）。判据=流程推进。
3. **前端校验绕过**：加密/签名在前端 → browser-auth 路线（真实浏览器合规登录）。
4. **验证码绕开**：接口直调不带 captcha 参数（前端校验型）；手机号分号分隔多账号。
5. **找回/改绑链**：重置 token 可预测（auth-bypass 22 矩阵）；改绑接口未校验旧绑定。

## 五、L5 令牌伪造（jwt-crypto 承接）

- alg:none / 弱密钥（hashcat 限频）/ kid 注入 / RS256→HS256 混淆：伪造成功判据=
  用伪造 token 访问受保护接口返回 200 且业务数据生效。
- **合规边界（v5.1）**：伪造仅允许基于**已确证的伪造类漏洞**（弱算法/弱密钥/可预测结构）构造
  **自建会话**；禁止窃取或重放**真实用户的活跃会话/token**（冒充真实用户=越权+隐私问题，
  且会触发客户侧风控）——观测到他人 token 只登记泄露面，不重放。

## 六、L6 会话构造（最后手段，均需判据）

- 会话固定（登录前后 cookie 比对）、可预测 session（自增/base64(userid+ts)）、
  多端互踢缺失（旧 token 登出后重放）。
- **合规边界（v5.1）**：同 L5——构造的会话必须来自**可推导的缺陷**且仅用于自有测试对象；
  会话固定/预测验证使用自建或客户提供的会话，禁止以真实用户会话为实验材料。

## 七、纪律与红线

- 爆破类动作严格受 weak-cred-bruteforce 锁定规避纪律约束；注册类动作按 ROE
  `identity.auto_register` 门控（v5.1 默认 deny=只评估不注册；allow 时仅建自建测试账号并
  登记 S7 清理清单）；**任何"拿到身份"必须 record_loot 掩码登记**；
  身份获取尝试全部 update_coverage（auth 类）——失败的路径（如"注册关闭"）也要登记，
  防止回环重复试探。

## 八、v4.8 W4 六轨编排协议（引擎编排层强制）

> 引擎已编排化：无凭证且有登录面时 s4 上下文注入编排提示，s4 收口门硬校验逐轨 VT 留痕（[W4-L1]..[W4-L6]）。

1. **逐轨尝试、逐轨登记（VT 化）**：每轨开工即 record_vt（title 前缀 `[W4-Ln] <轨道名>：<一句话目标>`，ready_assets 写就绪脚本/字典路径）；轨完成立即 update_vt 处置（executed 附 result_ref / closed-roe 附理由 / deferred 附三要素）。**不适用轨也登记**（如无 OAuth 面时 `[W4-L5]` 的 start_conditions 注明「无对应面」）——与筛查矩阵三态口径一致，禁止空口跳轨。
2. **命中轨分类处置（v5.1）**：L1 为评估轨——deny 下"命中"=发现注册面（记 finding/VT），**不建会话不注册**；L2-L6 任一轨真正取得身份（verified loot）立即 load_skill session-state-chain 建会话并登记，后续认证后测试转有身份流程——身份获取是手段不是终点（破解即终点=零转化）。
3. **L4 验证码轨闭环编排**：captcha-ocr「取码→识别→立即提交」**单会话闭环**（跨会话复用识别结果=假阴性，evidence-standard 口径）；分割数不符返回 None → 降级人工读码（request_user_input）或 browser-auth 会话路线，不硬套。
4. **凭据面预言机分流**：无验证码面用 browser_oracle 直连探针（枚举/锁定预言机标准化）；SimCaptcha 类面先建会话再探（通道注入态）。
5. **全轨失败移交链（v5.1 补索取闭环）**：六轨全未命中（或 L1 被 ROE 关闭且其余轨未命中）→ 六轨 VT 全量登记 → **先执行一a节身份索取闭环（request_user_input 向客户索要测试账号）** → 客户拒绝/超时才按 S4-7 收口摘要三行报告（匿名确证高危数/路线尝试记录/认证后项处置状态）将认证后项统一标 needs_follow_up 移交——禁止未试路线就整体放弃，也禁止跳过索取直接放弃。
