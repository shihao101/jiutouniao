# 钓鱼基础设施与邮件攻击面

**定位**：钓鱼模拟的**基础设施与可达性评估**（s6-4 钓鱼模拟的支撑剧本）。默认只做**只读判定**（SPF/DMARC/发信可达性），投递演练需 ROE 明确允许 + 授权收件人清单；不提供任何针对真实用户的欺骗内容生成。

## 一、邮件域防护判定（L0 只读，S2/S6 均可执行）

```bash
# SPF：无记录 / +all / ?all = 任意人可伪造该域发信
dig +short TXT target-domain.com | grep -i v=spf
# DMARC：p=none = 不拦截（伪造邮件进收件箱）；p=reject = 强拦截
dig +short TXT _dmarc.target-domain.com
# DKIM 选择子枚举：dig +short TXT selector1._domainkey.target-domain.com（常见 selector 清单试到命中）
```

- **判定矩阵**：SPF 缺失+DMARC p=none → 伪造发信可达（高危发现，伪造成本≈0）；仅 SPF 缺失 → 依赖接收方策略（中）。
- 影响证明口径：构造一封**发给自己**的伪造测试邮件（From: 伪造域, To: 自己邮箱）证明投递成功，截图留证，不涉及任何真实用户。

## 二、可达性延伸判定（只读）

- **MFA 面**：登录口是否暴露 OTP/MFA 推送（auth-flow-deep 的 MFA 段）→ 结合 DMARC 缺失评估"伪造邮件引导至假登录页"的可行性（写推演，不实施）。
- **品牌资产**： logo/命名规范公开程度决定仿冒页可信度（推演口径）。
- **邮件网关**：MX 记录指向（企业邮箱/云网关）→ 已知网关 CVE 面（cve-weaponization 衔接）。

## 三、投递演练（ROE 明确允许时的最小流程）

1. 收件人清单限**授权测试组**（一般 3-5 人，书面列名）；
2. 测试邮件主题/正文由 LLM 生成模板后**人工过目**再发；投递统计只记"是否到达/是否被拦截"，不统计谁点了（避免引入人员考核争议）；
3. 发信通道用测试域（不仿冒真实第三方品牌），SPF/DKIM 按测试域正常配置；
4. 演练结束 24h 内在报告中删除任何可关联到个人的记录。

## 四、纪律

- 本剧本全部产出进报告「安全向量/盲区」与推演章节；**不生成对真实用户的欺骗内容**（定向模板须 ROE+授权名单双重门禁）。
- DMARC/SPF 缺失类发现按 vendor：`邮件域: <域名>` upsert_fact + record_finding（中/高按 p= 档位）。
