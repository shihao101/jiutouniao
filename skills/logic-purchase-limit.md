# 购买限制与订阅权益绕过

**定位**：一切带"仅限一次/首单优惠/仅限 N 台/签到送 VIP/会员权益"标记的业务流。核心判据只有一条：**反复触发后权益/订单是否叠加**。

## 核心手法（五变体）

1. **不付款无限建单**：抓首单创建包 → 反复提交（可换配置/规格/双端多开窗口）→ 判据=每次返回**不同订单号且均可支付**。定级：权益**时间不叠加=中危，可叠加=高危**。
2. **支付地址重放/复用**：订单支付路径（如 `/qrbe/XXXX`）重放生成新支付地址（观察末段差异）→ 再次付款权益续期。判据：VIP/会员到期时间前进。
3. **路径段枚举**：支付路径差异仅末 6 位 → 直接爆破路径枚举他人/新订单，无需重放数据包。
4. **签约续费占位绕过**：支付即签约自动续费，续费状态占用"已购一次"标记 → **先关闭自动续费** → 旧订单/旧支付页（含刷新后的二维码）可继续复购。判据：关续费后原支付地址仍可付款。
5. **订单不消失复刷**：支付完成后订单列表不清除已支付单 → 重放支付请求批量刷权益（案例：6 元=34 天会员）。

## 配套变体

- **四舍五入精度差**：余额与第三方支付只到"分"——充值 0.019 显示 0.01、到账 0.02；**举一反三到提现侧**（提现 1.005 实收更多）：同一模式换功能点复测。
- **代金券拆分并发**：大额券拆多次小额订单，最后一次并发两单（Turbo Intruder，见 race-condition）→ 均扣券均成单。
- **本机时间信任**：客户端以本地时间判权益 → 领最短试用 → 系统时间前移 → 特权功能仍可用（以**功能可用性**为判据，非页面标签）；时间后移做反向验证。
- **阶段奖励跳步**：走一次全流程拿到"置完成态"+"领取"两包，step 参数与任务序号一一对应 → 直接构造第 N 任务。

## 纪律

- 全程小额/零成本验证（不产生真实大额消费；测试支付后如可退则走退款流程并登记）；
- 每个变体命中 → record_finding + 定级按叠加规则；全不中 → ruled_out 附五变体清单。
- **无凭证三态路由（v5.1）**：①客户提供测试账号 → 全流程；②仅匿名 → 支付路径结构识别与端点枚举（匿名可做），下单/复购/券类单元逐条 record_vt/needs_follow_up 移交（禁止静默跳过）；③无入口 → needs_follow_up 显式登记。「他人订单」枚举仅限**客户提供**的测试账号 B，禁止触碰真实用户订单。禁止自动注册（ROE identity.auto_register）。
