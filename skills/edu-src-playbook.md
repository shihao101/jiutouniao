# 教育/高校行业攻击面 SOP

**定位**：教育/高校授权项目的行业化打法（与其他行业化 playbook 同构）。授权确认后按本 SOP 组织 S1/S2。

## 一、高校高价值系统优先级（进门户后按序打）

一站式服务大厅（SSO 总入口）→ 人事系统/学工系统（数据最全）→ 考试/阅卷/评分系统 → 直播/点播/录播系统 → webvpn → 统一身份认证。**webvpn 域名规律**：`10-20-100-236.webvpn1.xxx.edu.cn` 即内网 10.20.100.236——可直接还原内网拓扑。

## 二、个人身份四件套（行业万能钥匙）

关键字段：`xh`（学号）/`sfz`（身份证）/`gh`（工号）/手机号——互可反查。**谷歌语法组合拳（按序）**：
1. `site:xxx.edu.cn sfz` / `site:xxx.edu.cn xh` / `site:xxx.edu.cn 初始密码`
2. `site:.edu.cn sfz filetype:pdf|xls|doc`
3. 来源优先级：学校主站公示页（`/info/1017/1222.htm` 模式）→ 当地教育局站点（助学金/奖学金公示必带 sfz）→ 附件文档
4. 泄露的 sfz 可反查 xh，组合成登录字典素材（初始密码规则常为身份证后六位/学号）

## 三、fofa 收缩链（资产批量定位三层法）

1. `"系统名" && org="China Education and Research Network Center"`；
2. 判据：某图标下**独立 IP 数 = 在用该系统的学校数量**（数字越大通杀价值越高）；
3. 从指纹里提取**厂商名** → `"厂商名" && org=...` 二次收缩 → 默认密码 → **返回包跨校复用**（案例：A 站成功响应整体替换 B 站失败响应放包进后台，400+ 站点）。

## 四、厂商默认密码四条路（进后台的主要手段）

① SRC 开发商排行榜列厂商 → 搜「厂商+系统名+操作手册/默认密码/管理员手册」；② 目标门户"帮助说明"页常直接写初始密码；③ 企查查收集厂商命名习惯（如 wrd/wrdtech/webvpn）构造字典（`wrd@123`、`wrd!@#qwe123`）；④ GitHub 搜厂商仓库找密码样式。**默认口令样本入库**：admin/admin、admin/123456、WRD 系统 `admin/Wrd123!@#`、学工系统"密码=账号"、首登强制重置 `Test123#`（批量判断未重置账号=通杀）、人事系统 `66xx66` 模式。

## 五、教育 SRC 案例利用链（参考路径）

定点链：选漏洞少的学校 → 主站公示页泄露 sfz → 反查 xh → webvpn/一站式大厅爆破 → 帮助说明得初始密码 → 人事系统弱口令 → 学工系统改 id 水平垂直越权 → 任意密码重置拿管理员（改包）→ 考试系统添加用户改 `ddlRole=0` 越权创建管理员 → 上传点图片马+`/.php` 解析 → 内网（**授权边界外止步**）。

## 六、战术纪律

- 遇 WAF 的注入只试一个单引号报错+闭合，不行果断换系统（效率优先）；
- edu 不值得深挖 XSS（仅控制台弹窗验证）；
- 顺序固定：弱口令 → 改返回包登录 → JS 找未授权接口 → SQL → 逻辑爆密码 → 信息收集进后台；
- 进 webvpn 后内网定位：一站式大厅点开全部应用 → ping 收集 IP → **二分法 ping B 段**存活 → fscan 弱口令/nday（**严格核对授权边界**）；
- 代码审计上分：文库（历史 OA payload）先打站再下源码二开；GitHub/网盘找源码。

### 渠道补全

语雀渠道：公开文档检索目标学校敏感信息（文档/手册/密码说明）。非站内渠道：班群、表白墙等易泄露身份信息的社交面。代码审计取源码补「咸鱼」渠道（与 GitHub/网盘并列）。上传实测行为差异记录：Nginx `/.php` 解析漏洞改后缀抓包上传失败，但**直接上传完整哥斯拉马反而成功**；一句话木马可命令执行但连不上 webshell 管理器——"改后缀不通就直传完整马"的实测差异，不定式，逐一实测。
