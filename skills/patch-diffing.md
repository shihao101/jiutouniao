# 补丁差分（Patch Diffing）

目标：**在没有公开 PoC 时**，从补丁/提交差异反推漏洞机理 → 生成检测探针 → 受控验证。适用于：有补丁无 PoC 的 Nday、同版本自建环境的安全版本对照、以及组件历史版本审计。

## 步骤

1. **版本定位**：精确确认目标组件版本（cve-weaponization 的指纹判据先行）；无补丁版本号时差分无从谈起，先回指纹技能。
2. **差异来源**（按可用性）：
   - 官方安全公告中的修复 commit/patch 链接（GitHub Advisory/厂商公告）；
   - 相邻版本源码包对照（安全版 vs 受影响版，diff 工具）；
   - 发行版补丁页（distro tracker）。
   **来源合法性**：公开仓库/公告页拉取（scopeGate 白名单域），不使用泄露/未公开材料。
3. **差分解读四问**：
   - 改了哪个函数/校验？（定位漏洞类型：缺过滤=注入类、新增鉴权=越权类、长度/边界=溢出类）
   - 修复前数据流是什么？（source→sink 路径，接 whitebox-sca-taint 表）
   - 触发条件是什么？（参数形态/前置会话/配置开关）
   - 能否构造无害探针？（回显差异/时间差/布尔分支，对齐 hypothesis-0day 最小差异法）
4. **探针构造与验证**：探针必须**无害**（存在性证明口径）；验证结果按对应漏洞类技能判据定性；受影响版本 vs 已修复版本的**双环境对照**是最强判据（差异只在受影响版复现）。
5. **未修复环境的证据链**：探针请求/响应 + 版本指纹 + 公告链接 + 差异摘录四件齐 → record_finding（confidence 按实测）。

## 判据

- 确证：探针在受影响版本稳定复现 + 机理与补丁差异一致 +（可选）修复版不复现。
- 疑似：仅版本匹配、探针无法区分补丁前后 → 不确证，VT 保留并注明缺口。
- 无补丁可差分：转 hypothesis-0day 行为差异法，本技能不做。

## 记账

- 差异解读写入 upsert_fact（key=`patchdiff.<组件>.<cve>`，value=机理一句话+触发条件）；
- 探针/响应落 evidence/；coverage 单元 vuln_class 用真实类名（notes 引 CVE 与差分文件）。

## 工具可用性探针

`which diff git curl wget`（git 逐 commit 差分、diff 逐文件对照）；拉取公开补丁走 run_command 白名单域；不可用 → 请求数据包人工对照，VT 注明降级。

## Execution Profile 标注（v5.3.2）

- 公开资料拉取与本地差分全只读（L0）生产档可执行；
- 验证探针按漏洞类对应技能档位；**禁止**对目标做破坏性利用来"验证补丁"（存在性证明口径）；
- 差分工件只入项目工作区，不分发。

## 关联技能

cve-weaponization（版本指纹与公告检索）、whitebox-sca-taint（数据流表）、hypothesis-0day（探针差异法）、poc-template（探针脚本化）。
