# 业务状态机滥用手册（C-19 状态变更 / C-20 限次配额 / C-18 金额边界 / C-06 注册默认态）

> 触发条件：存在**多步业务流程**（下单/审批/工单/充值/兑换/配额消耗）。目标不是找注入，而是让服务端接受**合法状态图之外的转移**。

## 〇、前置与纪律

- 全程 L1 起步（占位数据）；任何**写转移**（真实状态变更）必须 L2 工单 + 占位测试数据 + 最小请求预算；
- 每条非法边测试 ≤3 次重试；整个状态机审计 ≤25 请求/应用（超出 → record_vt 移交）；
- 证据 = 请求/响应对 + 状态前后快照（计数/哈希/关键字段），**只做存在性证明不批量操作**；
- 无凭据：C-19/C-20 的会话前置项按 identity-bootstrapping 结论移交 deferred，**匿名可达的边照测**。

## 一、合法状态图还原（先画图再打）

1. 从 UI 流程（前端路由/按钮 disable 条件）+ API 观察（响应里的 status/orderState/node 字段）枚举合法状态；
2. 用 `logic-invariant.py`（默认 dry-run）登记状态变量：`python3 /opt/tools/logic-invariant.py --base <t> --flow <流程名> --states "created,pending,approved,rejected" --dry-run`；
3. 标注每个转移的**发起角色**与**前置条件**（谁有权、从哪状态、需要什么 token）。

## 二、非法边生成（五类违例，每类一个最小探针）

| 违例 | 探针 | 阳性判据 |
|---|---|---|
| **跳步** | 直接请求终态转移（如未支付先调 `/complete`；未审批先调 `/BatchApprove`） | 200/302 且状态字段实际变化 |
| **逆序** | 合法序列倒放（先 reject 后 submit） | 同上 |
| **重复** | 同一转移请求**原样重放 ×2**（幂等缺失） | 第二次仍产生副作用（计数+2/重复记录） |
| **跨对象** | 对象 A 的上下文调用对象 B 的转移（body 换 id/guid） | 副作用落在 B 上（对照 C-08） |
| **角色错位** | 低权会话调用高权转移端点 | 转移成功（对照 authz-diff BFLA） |

## 三、竞态与限次（C-20）

- 同一请求 **并发 ×2-5**（`curl --parallel`/bash 后台 &：`for i in 1 2 3; do curl -s -b jar -X POST ... & done; wait`）——**单应用 ≤5 并发、一次测试会话总量 ≤15 请求**，禁止高频压测（ROE 禁 DoS）；
- 配额类（投票/领取/核销）：同账户连续消耗至配额边界（≤5 次），观察边界校验；换标识（uid/设备头）后配额是否重置；
- 判据：**服务端去重缺失**（并发全部成功）→ record_finding（CWE-362/CWE-641）；边缘 WAF 429 拦截 → waf_blocked 如实记账。

## 四、金额与数量边界（C-18，仅 isolated_lab 或 L2 工单）

- 数量/金额：0、负数、超大值（10^9）、小数精度（0.001）、币种混用；
- 判据：负数/0 被接受且改变余额/库存 → 高危（写，必须 L2 工单 + 占位对象）；前端校验后端缺失但**写被拒** → 阴性；
- `race-condition` 技能承接并发提现/重复核销类验证。

## 五、注册与默认态（C-06）

- 注册响应/首登响应里**默认角色字段**是否客户端可控（role=member→admin）；重复注册同账号行为；批量注册限制（≤3 次）；
- 判据：越权默认态成立 → 高危（结合 authz-diff 验证该角色实际能力面）。

## 六、产出纪律

- 每条非法边 = 一个覆盖单元（`update_coverage` 引用 C-19/C-20，Notes 记"边: <from>→<to> 违例类型"）；
- 确证发现 record_finding（claims 必须含请求对文件 + 状态快照 must_contain）；
- 写转移在 production_safe 被治理门拦截 → 记 **blocked**（工单引用），不伪装阴性；无凭据项 → deferred 附启动条件；
- 收口前跑 `primitive-graph`：状态转移成功通常 = WRITE/AUTHZ 原语，入凑链图。
