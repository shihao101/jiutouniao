# 安全设备/管理面剧本（v4.6 A1，承 某安全设备管理面目标 实证打法）

适用：国内主流安全设备厂商的 Web 管理面（自签证书、登录加密、UA 过滤、反脚本机制）。

## 一、扫描降档（K3 硬规则）

设备指纹确认后：禁 top-1000 以上扫描、禁并发全端口（实证案例：36 分钟窗口被扫描自伤烧掉 14 分钟）；
改为 T1 top-100 单线程 + 定向端口协议验证。

## 二、登录协议还原（离线优先）

1. 抓登录页 JS→定位加密入口（Emscripten/WASM：`cryptoParam.wasm` 类）→
   wasm2wat 反编译→本地复现 oracle（目标：单测向量 ≥3 组全对齐才算还原）；
2. **WASM 二进制必须当场落盘**（差 1 个请求 = 整条登录链搁浅，实证案例）；
3. CLI 构造请求头签名（token 一次性队列类）：HAR 地面真值 + 单变量差异实验定性失效根因
   （重放/坏签名/空闲超时三假设分测）。

## 三、反脚本机制绕过

脚本客户端被拦 → 真实浏览器自动化（`--headless=new` 无自动化特征；JS 重建表单后注意
密码框 id 变化）；登录成功立即 channel-snapshot（K1 强制）。

## 四、边界评估

管理员立足点后的重心是边界评估：能力位掩码/挂载面/SA token/IMDS 单脚本白名单采集
（privesc-checklist 联动）；写类动作（改密/重启/网络配置）默认禁止，ROE Profile 显式允许才执行。

## v4.8 M6 工具通道兼容性声明

> 口径（loop-core v4.8 纪律 3）：先 probe 后 batch——每个外部工具对目标首次使用前先用小样本探针确认可用性，探针被拦/挂起先切适配通道再批量；探针结果写入交付物工具声明小节。各工具在「挑战型 WAF / 封闭站」下的可用性与适配通道：

- curl：低频手工请求始终可用——也是挑战态复放的最小工具（channel-snapshot 快照 cookie/UA 复放）；禁用它做大批量枚举。
- channel-snapshot.py：适配通道本体（挑战态提取/复放）——挑战型 WAF/封闭站下始终可用，且是本清单其它工具的适配通道来源。
