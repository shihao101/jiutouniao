# 0day 假设驱动测试工作流

自动化工具只覆盖已知漏洞；**0day/新漏洞来自「对异常的系统化追问」**。本手册是与覆盖矩阵、失败反馈环配套的通用工作流，适用于一切漏洞类。

## 四步法（每个异常一轮，全程留证）

1. **异常观察**：响应长度/时间/状态码/内容/行为与预期偏离。例：参数 X 变化时响应跳变 300B；同接口不同请求耗时差 2s；报错泄露半条 SQL。
2. **差异假设**：用一句话写下可证伪假设——「X 未过滤直接进 SQL 拼接（数字型）」「Y 是模板变量」「Z 是缓存键」。一次只验证一个变量。
3. **最小差异验证**：构造基线 vs 变异对，差异必须单变量：
   - 基线 = 正常请求原样；变异 = 只改假设涉及的那一位
   - 优选无害判据：布尔分支（AND 1=1 / AND 1=2）、算术求值（3-1）、回显位数（{{7*7}}）、时间差（WAITFOR 0:0:5）、OOB 回连
   - 每组跑 2 遍排除抖动；结果落 evidence/
4. **置信度定性**：确证 = 差异可稳定复现 + 判据机制明确（能解释为什么）；疑似 = 有差异但机制未证；待查 = 仅单次观察。定性后 record_finding（附 cwe）/ update_coverage。

## 触发源清单（去哪里找异常）

- 版本指纹与已知 CVE 对不上但组件行为可疑（cve-weaponization 零命中 ≠ 安全）
- 报错信息泄露的半截语句/路径/变量名
- 文档/注释/JS 里提到但接口清单里没有的端点（injection-points 挖出后行为怪异）
- 业务规则的反直觉边界（logic-csrf-deser 的场景清单）
- 同类参数在不同接口的处理不一致（A 过滤 B 不过滤）
- WAF 对特定 payload 的差异化拦截（拦截=存在检测=值得绕行分析，waf-fingerprint）

## 与其他机制的对接

- 每个假设注册为一个 coverage 单元（vuln_class 可写「0day-假设#N」），定性后改正式类名
- 验证失败 → premise_failed + 修正假设（失败反馈环）；连续 3 轮无进展 → consult_expert
- 确证的 0day 候选：影响评估 + 最小 PoC（poc-template）→ S5 受控验证；**不做破坏性利用**

## 纪律

- 异常≠漏洞：没有差异证据不下结论（差异测试通用化）
- 不为凑数制造假设：每个假设必须有观察依据
- 0day 候选在报告中单独成节，标注「授权范围内发现，未公开编号」

## Execution Profile 标注（v5.3.2）

- **Lab Only 动作**：0day/nday 假设的全链验证执行（生产档以无害探针与回显证明可达性）——仅 isolated_lab（可快照回滚的隔离靶场，项目显式声明）可执行；production_safe 下引擎逐动作强制禁止（v5.3.1 governanceGates 全通道确定性拦截并留证），不要尝试绕行。
- **production_safe 口径**：只做存在性证明（无害回显/随机标记/受控 OOB/量级与哈希证明），可达性证明即止。
- **工件处置两档分流**：生产=四元组（路径/指纹/建议清理命令/验证命令）登记移交《需人工清理清单》；实验室=快照恢复/环境重置回收（恢复成功须只读验证）。两档均不执行目标侧删除/还原。
