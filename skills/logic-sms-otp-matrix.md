# 短信/邮箱验证码攻击矩阵

**定位**：任何"验证码+手机号/邮箱"流程（登录/注册/改密/改绑/签署/支付确认）的系统化测试。**六条路径互为备选：一条不中换下一条**。全部为低影响验证（不实际接管账号、不轰炸真实用户）。

## 路径一：响应回显

触发发码 → 立即检查该响应与同页全部 XHR 响应 → 找 code/sms/captcha 字段。**变体**：明文 / base64 等编码（解一遍再试）/ 出现在初始化或统计类旁路接口。

## 路径二：位数爆破

**前置判据（三条件同时满足才打）**：码 4 位（6 位耗时 100 倍，谨慎）+ 有效期 ≥5 分钟且实测不真实失效（宣称 60s 常不真实生效）+ 无失败次数锁定。步骤：intruder 对校验接口 code 参数跑 0000-9999；**改密点优先**（无需原密码）、注册点次之（→任意注册）、支付点再次。判据：返回包出现成功/跳转/长度差异。变体：邮箱验证码同样常无次数/时间限制（改绑邮箱处爆）。

## 路径三：验证码复用

前置判据：连发多次码相同、有效期窗口大。步骤：完整走一遍改密/登录 → 用**同一个旧码**重走第二遍流程（识别码变了但流程可继续 = 未消费）。

## 路径四：码与手机号未绑定

步骤：填目标身份触发发码 → 翻请求/工作台找 mobile/phone 参数 → **改为自己的手机号** → 用自己收的码完成他人流程。判据：自己收到针对目标身份的码。变体：A 的码 B 可用、同号双码均可用。**同族**：签署/改绑流程中电话参数可控=代签/代改绑（改电话收码越权）。

## 路径五：响应包替换

正确码走一遍保存成功响应 → 错误码重发时拦截**响应**整体替换为成功响应 → 流程放行。判据：服务端以回传参数作最终凭证、或仅前端校验的流程。**快速判据（v5.6.0 修订：以复现对照取代经验概率）**：验证码校验步骤的响应包里没有 token/sign 类可校验字段 = *候选信号*（仅提示，不计入 coverage 结论）——必须按正负对照闭环：①正例：拦截响应整体替换为成功响应 → 流程真实放行且服务端状态变化（复读服务端状态留证，联动 race-condition 复读纪律）②负例：不拦截重放原始流程 → 放行失败。正例稳定复现 2 次 = 确证；正例命中但服务端状态无变化 = 前端假放行（低危/信息）；仅凭"无校验字段"不得直接定级。

## 路径六：任意注册两个模式

①注册响应包直接回显激活链接（访问即激活）；②4 位码 + 15 分钟有效期 → 路径二爆破完成任意注册。

## 轰炸/频控绕过变体（仅限授权频控有效性验证，不做真实轰炸）

- 手机号变形：部分位 URL 编码（%31%37，任意前 2/3/4 位）、前后空格、86/086/0086/+86/0/00 前缀、\r\n、特殊符号；
- 12 位号码 → 网关截取前 11 位照发；邮箱侧：大小写变形（qq.coM）绕发送次数限制，逐轮变形+并发；
- 通用：改 cookie/变量/返回值；无防护时 re 重放或 Turbo Intruder 并发。

## 纪律

- 轰炸类只验证**频控是否有效**（3-5 次变形命中即记录），不对真实用户持续轰炸；
- 每条路径命中 → record_finding + update_coverage；全不中 → ruled_out 附六路径已测清单；**同根因升级确证后原疑似记录 detail 标注取代关系**。

### 实战补遗（v4.4 一线 SRC 实战实证，已去标识）

- **回显形态扩展**：验证码回显不止明文 code 字段——留意响应里 base64/其他编码形态的码值，逐字段解码核对；"响应里没有 code 字段名"≠无回显。
- **短信限流绕过头族（实测增量）**：手机号**部分 URL 编码**——`17→%31%37` 后接 699999999、前 1/3/4 位分别编码均可行（网关解码归一化不一致）；号码变体族：前后空格/86/086/0086/+86/0/00/\r/\n/特殊符号；12 位号码短信网关截前 11 位；修改 cookie/变量名/伪造返回包；邮箱场景大小写变体（`@qq.coM`）绕发送次数限制。
- **邮箱轰炸同构**：发信次数限制的绕过与短信同族（大小写/变体/并发）；并发工具 Turbo Intruder 配合。
- **合规口径**：轰炸类仅做**小规模受控验证**（证明限流可绕过 2-3 次即停、不投递真实骚扰量），证据=绕过成功的响应对比；record_finding 写明"限流可绕过"而非"可轰炸"。
