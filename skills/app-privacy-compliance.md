# 个人信息合规检测手册（技术取证视角，补「报告-管理建议」章节；非法律意见，结论供合规评估参考）

## 一、收集行为取证（静态）

```bash
# 权限声明 vs 实际使用：AndroidManifest/Info.plist 权限清单 → 代码里对应 API 调用位
# 超范围收集判据：未声明权限却调用（getDeviceId/定位/通讯录/短信）
# SDK 收集：第三方 SDK 清单（统计/推送/广告）→ 各自隐私政策一致性
# 设备指纹：IMEI/MAC/AndroidID/OAID/IDFA 采集位与频次（首启即采=违反最小必要候选）
```

## 二、传输与存储取证（动态/流量）

```bash
# 明文传输个人信息面（app-dynamic-audit 抓包对照）：HTTP 明文、自签名忽略校验的通道
# 本地存储：sharedPreferences/db 中明文个人信息（测试设备自有账号数据）
# 上报频次：首启后 N 分钟内的埋点请求计数（频繁上报=合规观察项）
```

## 三、隐私政策一致性（人工核对点清单）

- 政策是否列明 SDK 清单与收集目的；撤回同意入口是否存在（设置页判定）；注销通道可用性；儿童模式声明。
- 首启弹窗时序：**先收集后弹窗** = 判据级违规候选（抓包时间线证明）。

## 四、产出口径

- 输出《个人信息处理行为核对表》（收集项×必要性×政策一致性×证据路径），只描述行为**不下合规结论**（结论由法务/合规出具）。
- 证据：抓包原文（Burp 对照格式）+ 静态调用位截图，逐条 EV 编号。
