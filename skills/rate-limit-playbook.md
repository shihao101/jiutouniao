# 限速/连接级阻断目标剧本（v4.6 K3/K4）

> 审计实证：某限速分型目标/某限速分型目标 两个任务 9.7h 名义窗口真实交互 <1h——
> 全部损失来自"扫描自伤 + 冷却期高频探活 + 教训未检索"。

## 一、扫描 governor（开工前必算）

- 有效 conn/s = min(设定速率, 关闭端口 RST 即返速率)——`-min-rate 300` 对全关端口实际 ≈400 conn/s；
- 指纹=安全设备/WAF/管理面 → 强制降档（--min-rate ≤50、串行、禁后台并发扫）；
- 首次 HTTP 000/超时突发 → 立即全面降档并 record_lesson（behavior_class=rate-limited），禁止归类"偶发"后继续全速。

## 二、冷却协议（默认完全静默）

- 触发阻断 → **零探活**（探活可能重置锁定窗口——某限速分型目标 观测，未实验验证前不得反向采信）；
- 金丝雀：静默 15min → 单请求探活；失败 → 45min → 90min 指数退避；
- 「完全静默 ≥60min 恢复、周期探活重置锁定」已入组织教训（behavior_class=rate-limited）——S1/S2 承接限速类目标时载入本技能并执行该默认。

## 三、窗口化批量执行（冷却结束后的唯一正确姿势）

单窗口 ≤6-10 请求（优先消耗「就绪未执行」队列：脚本/PoC/参数字典先备好），
窗口内含 1 个金丝雀请求；窗口结束立即回到静默。禁止三轮各排各的——开工时一次性排好全部窗口时刻表。

## 四、探针脚本纪律

- 每个探针自带重试与退避（8s 起步），失败结果标 `observed_result=undetermined_timeout`
  （coverage 用 needs_follow_up，**不得 ruled_out**）；
- 「脚本就绪未执行」必须在收口清单 ready_but_unexecuted 逐条列明（引擎 V3 强制）。

## v4.8 M6 工具通道兼容性声明

> 口径（loop-core v4.8 纪律 3）：先 probe 后 batch——每个外部工具对目标首次使用前先用小样本探针确认可用性，探针被拦/挂起先切适配通道再批量；探针结果写入交付物工具声明小节。各工具在「挑战型 WAF / 封闭站」下的可用性与适配通道：

- curl：低频手工请求始终可用——也是挑战态复放的最小工具（channel-snapshot 快照 cookie/UA 复放）；禁用它做大批量枚举。
- channel-snapshot.py：适配通道本体（挑战态提取/复放）——挑战型 WAF/封闭站下始终可用，且是本清单其它工具的适配通道来源。

## v4.8 W5 出口池增补（单出口降级不拖垮全局）

- 出口池标准件：`python3 /opt/tools/exit-pool.py --config exits.json --next`——轮换输出出口与会话分片目录；`--health` 探活；出口失效 `--degrade <name>` 标记（5 分钟内跳过，全降级显式错误不静默回退）。
- 限速语义与出口的关系：锁定态通常按 IP/出口维度——**单出口被锁定时切出口而非冷却等待**（行为预算器冷却协议仍生效：批量配额是全局的）；出口配置（住宅代理等）为外部资源决策，配置文件即接，标准件不携带任何代理资源。
- **W5 与冷却协议的判定顺序（v5.1，消除"切出口 vs 静默"二选一硬套）**：先判**锁定维度**——①路径级 RST（基线正常，仅特定路径 000）→ 换路径继续，不切出口不静默；②IP/出口级（本出口基线 000，其他出口未知）→ 有出口池时切出口并延续全局配额，无出口池时进入冷却协议；③全局级（双基线+出口均 000）→ 完全静默冷却（§二口径），锁批量动作转零流量工作。判定依据=双基线探针（封锁判定流程），证据落 evidence/。
- 轮换节奏：批量动作按出口轮转分片推进（每出口独立快照态），单出口连续 2 次空壳即切下一出口（配合行为预算器空壳即停）。
