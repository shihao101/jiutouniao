# 全封闭站点剧本（v4.6 A1，承 某全封闭站目标 实证打法）

适用：边界层对未授权路径统一 403/508/502 的目标（Server 头统一 none）。

## 一、绕过矩阵（单命令批量落盘，一轮排除）

按序批量（每类 1 请求，全部对照基线）：Host 变体×8 / 路径规范化（/./、/../、//、;、%2e、
大写、尾斜杠；curl 必须 --path-as-is）×12 / 头注入（X-Original-URL/X-Rewrite-URL）×6 /
方法×4（HEAD 返 502 是常见指纹陷阱，判活用 GET） / UA 变体×2 / cookie 重放 / 走私×2。

## 二、判定纪律

- 全部变体命中同一 403 页（同字节数+同文案）→ **白名单完备**（negative_valid，可 ruled_out）；
- 任何变体响应字节/文案偏离基线 → 单变量放大复验 3 次，仍偏离才升级；
- robots.txt/sitemap 通常在白名单内，先取（历史 URL 结构/影子资产线索）；
- 白名单按精确路径匹配时，「同类端点逐一排查」——一个遗漏不代表机制失效（某网关过滤目标 单端点遗漏案）。

## 三、收口

负结果逐项落黑板防重复试错；应用层不可达≠测试完成——把「绕过面已穷尽」与「应用层零触达」
分两个单元入覆盖矩阵，S8 分开陈述。

## v4.8 M6 工具通道兼容性声明

> 口径（loop-core v4.8 纪律 3）：先 probe 后 batch——每个外部工具对目标首次使用前先用小样本探针确认可用性，探针被拦/挂起先切适配通道再批量；探针结果写入交付物工具声明小节。各工具在「挑战型 WAF / 封闭站」下的可用性与适配通道：

- curl：低频手工请求始终可用——也是挑战态复放的最小工具（channel-snapshot 快照 cookie/UA 复放）；禁用它做大批量枚举。
- channel-snapshot.py：适配通道本体（挑战态提取/复放）——挑战型 WAF/封闭站下始终可用，且是本清单其它工具的适配通道来源。
