# 小程序备案、隐私披露与 SDK 治理证据（specB2 W10 配套——治理检查项，非漏洞分类）

> 定位：把备案主体/标识、权限说明、隐私政策、SDK 收集与数据删除路径作为**独立治理检查项**——核验隐私接口调用前的授权状态、提审声明与运行行为一致性；**与技术漏洞分开定性**（W6 汇入口径），不做法律结论、不自动变更备案。
> 边界（深度研究 W10 节）：备案核验仅限**客户自有小程序**（官方查询渠道 + 带时间戳截图）；平台隐私接口的 API 名与行为**逐基库版本重新核验**（微信/抖音文档路径不保证稳定，不沿用旧资料路径下结论）；法律/披露充分性判断留给客户治理责任人，本技能只做**一致性证据收集**。

## 一、治理证据盘点（产出《治理一致性证据表》）

| 盘点项 | 观测方法 | 喂养的测试项 |
|---|---|---|
| 备案主体/标识 | 官方备案查询（客户自有小程序）+ 小程序内页面声明 | T1 输出 |
| 权限说明 | 提审声明的权限用途 vs manifest/运行时权限触发 | T2 比对 |
| 隐私政策 | 政策文本快照（版本+日期）：收集类型/第三方共享清单/删除路径 | T3/T4 比对 |
| SDK 清单 | 解包产物 SDK 面（app-static-audit 依赖树）+ 政策披露的 SDK 清单 | T4 比对 |

## 二、W10 治理检查矩阵（每项：步骤→判据→三态；全部只读证据收集）

| T | 检查项 | 步骤 | 判据 | 判定 |
|---|---|---|---|---|
| T1 | **备案与主体一致性** | 官方渠道查询备案状态 → 与小程序内声明主体/标识比对 | 声明主体与备案不符 = **Confirmed（治理差异）**；一致 = negative_valid | 治理确认/negative_valid |
| T2 | **权限提审声明 vs 运行行为** | 提审声明用途逐条 vs 运行时权限触发场景（app-privacy-compliance 取证联动） | 声明用途与实际触发场景不一致 = Confirmed（治理差异）；一致 = negative_valid | 治理确认 |
| T3 | **隐私接口授权状态路径** | 隐私接口调用前的授权状态核验（按当版平台文档 API 名逐基库版本核验） | 未授权先调用 = Suspected（平台行为差异需双版本复核） | Suspected/negative_valid |
| T4 | **SDK 披露一致性** | 政策披露 SDK 清单 vs 解包实测 SDK 面（app-sdk-privacy-behavior 运行时证据并入） | 运行存在但未披露 = Confirmed（披露缺失·治理）；已披露 = negative_valid | 治理确认 |
| T5 | **删除/退出路径披露** | 政策声明的删除/撤回路径是否可走通（只验证入口存在与响应，不执行真实删除——自有测试身份除外） | 声明路径不可达 = 治理确认；可走通 = negative_valid | 治理确认 |

## 二.5、命令骨架（T1/T4 最小可执行序列）

```bash
# T1 备案查询留证（官方渠道 + 带时间戳截图 → evidence/w10-filing-<date>.png）
#    小程序内声明主体快照（关于页/设置页）→ 双侧比对表
# T4 SDK 披露比对：政策披露清单 vs 解包实测
grep -rEo "(com\.[a-z0-9.]+|cn\.[a-z0-9.]+)" unpacked/ --include="*.js" | sort -u > evidence/w10-sdk-observed.txt
#    与政策披露 SDK 域清单 diff → 未披露 SDK = 治理确认（引用 D8 运行时证据交叉佐证）
# 判读纪律：本技能全部产出为「治理确认/差异」，禁止写进漏洞定级表 P0-P4 计数（W6 分开口径）。
```

## 三、判定判据（深度研究 W10 节口径）

- **Confirmed（治理差异）**：备案主体不符/权限用途失实/SDK 未披露/声明删除路径不可达——**这是治理发现不是技术漏洞**，进报告治理章。
- **Confirmed（技术）**：仅当隐私技术门被实证绕过（如未授权调用敏感接口并返回数据——那是 app-sdk-privacy-behavior/D8 口径，本技能不重复）。
- **未核实纪律**：平台文档路径不稳定 → 逐基库版本实测后标注；无法核实的声明项标「未核实」，不推断失实。
- **禁自动变更**：不代客户修改备案/提审声明/政策文本——差异清单移交客户治理责任人，不做法律结论。

## 四、Execution Profile 标注

- production_safe（默认）：全部只读证据收集；查询渠道官方；删除路径验证仅限自有测试身份。
- isolated_lab：不适用（本技能无高危动作，两档口径一致）。

## 五、产出对接

- 产出《治理一致性证据表》进 `deliverables/`（技术漏洞分开口径）；record_finding **不用于治理类发现**（治理差异进交付物与 report 治理章；仅 D8 联动的技术确证走 record_finding）；update_coverage(vuln_class=W10治理证据, notes 记 `T1-T5 三态`)；
- 配合技能：load_skill app-privacy-compliance（PIPL 取证）、load_skill app-sdk-privacy-behavior（D8 运行时证据交叉）、load_skill report-writing（治理章引用格式）。
