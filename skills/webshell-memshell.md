# WebShell / 内存马与落点管理

**定位**：S5 拿到命令执行/文件写之后"怎么落地、怎么验证、怎么登记、怎么清理"——java-deser/php-family 等剧本在「探针确认→转 S5」处断头，本剧本补全后半段。**前提**：ROE 允许驻留演示；默认仅演示即删，持久化需 ROE 明确允许。

## 一、落点选择（WRITE 原语 → 稳定 EXEC）

1. **可解析路径**：确认落点目录会被脚本引擎解析（已知站点根/可解析上传目录；上传目录禁解析的中间件配置下换思路：临时目录+包含/加载链）。
2. **权限与存活**：进程用户可写、目录不被定期清理（对比 tmp 与 webroot 的清理周期）、跨重启存活需求（ROE 允许才考虑）。
3. **最小痕迹**：文件名混入业务词（无随机后缀）、内容与站点编码一致、时间戳对齐目录既有文件——**只做痕迹最小化，不做免杀对抗**（专项 C 边界不变）。

## 二、连接器适配表（判据级，不展开流量构造）

| 连接器 | 兼容要点（验证用） |
|---|---|
| 中国蚁剑 | 一句话木马（`<?php @eval($_POST[x]);?>` 类）+ 编码器适配；连接判据=执行 `whoami` 回显 |
| 冰蝎（Behinder） | 加密流量（AES+密钥协商）；PHP/JSP/ASP 版本对齐；判据=命令回显+文件管理可用 |
| 哥斯拉（Godzilla） | 加密型，支持 JSP/PHP/.NET；负载器与密码/密钥/用户名三元组对齐；判据=基础命令+数据库管理连通 |

**纪律**：连接验证只在授权目标进行，payload 从 poc-template 派生并登记；连接器流量特征写入 evidence（证明是智能体自建，供 S7 清理与溯源）。

## 三、Java 内存马（无文件落盘驻留判据）

1. **注入通道**：反序列化 RCE / SpEL / JDBC 链等已有 EXEC 通道内完成注入（不新增上传面）。
2. **Filter/Servlet/Listener 三型判据**：
   - 注册后**路由探测**：请求魔术路由（如 `/this-path-not-exist-but-shell-does`）返回注入内容 → Filter 型成立；
   - **无文件验证**：`find <webroot> -newer <marker>` 无新文件 + 路由可达 → 内存驻留确证（这是内存马区别于文件马的核心证据）；
   - **重启失效性**：内存马天然随应用重启清除——但**智能体不触发应用重启**（v4.8.1 口径：重启属高风险操作），重启失效性作为「建议处置说明」写入记录清单移交人工。
3. **登记**：upsert_fact（`memshell.<路由>`：注入通道/路由/验证方法）+ record_loot(type=session)；**S7 不执行重启/卸载 Filter**（v4.8.1 口径）——卸载方法与重启建议写入《上传文件记录清单》移交《需人工清理清单》。

## 四、落点登记与移交清单（S7 强对接，v4.8.1 口径：所有智能体产生的驻留只记录不处置）

每个落点（文件马/内存马/新增账号/计划任务）创建时**同步**登记四元组，并写入**《上传文件记录清单》** `deliverables/s5-上传文件记录清单.md`：

- `路径/路由`（精确到文件名或路由）
- `指纹`（文件 md5 前缀 / 路由魔术值 / 内容标记串）
- `建议清理命令`（rm 精确路径 / 卸载 Filter 指令——**仅供人工处置参考，智能体不执行**）
- `验证命令`（人工处置后确认消失的只读命令）

**处置红线（v4.8.1 强制）**：**智能体产生的全部驻留（包含但不限于上传类：文件马/内存马/新增账号/计划任务/服务/SSH 公钥/启动项修改）只记录清单、不处置**——禁止执行删除（rm/del/atrm/schtasks /delete/net user /delete/reg delete/sc delete）、应用重启、Filter 卸载、文件还原等高风险操作；S7 不回收任何驻留工件，全部移交《需人工清理清单》（含四元组）。未登记的落点视为违规驻留（反思门会拦）；「能一条命令验证影响就不留第二分钟」的驻留最小化口径不变，验证后即停止使用而非删除。

## 五、与其他剧本联动

- 来源链：capability-primitive-search 的 WRITE/EXEC 等式；载荷构造回读 poc-template。
- 拿到 webshell 后的第一动作：身份确认（whoami/ip）→ 内网侦察入口登记（intranet-lateral/windows-lateral 承接）→ 权限边界实测（S6-1 权限矩阵）。

## Execution Profile 标注（v5.3.2）

- **Lab Only 动作**：写入 webshell 文件、注入内存马、注册 Filter/Listener 等植入动作——仅 isolated_lab（可快照回滚的隔离靶场，项目显式声明）可执行；production_safe 下引擎逐动作强制禁止（v5.3.1 governanceGates 全通道确定性拦截并留证），不要尝试绕行。
- **production_safe 口径**：只做存在性证明（无害回显/随机标记/受控 OOB/量级与哈希证明），可达性证明即止。
- **工件处置两档分流**：生产=四元组（路径/指纹/建议清理命令/验证命令）登记移交《需人工清理清单》；实验室=快照恢复/环境重置回收（恢复成功须只读验证）。两档均不执行目标侧删除/还原。
