# 无账号观测降级轨（无登录态 ≠ 不可测——用替代通道拿证据）

> 触发前提：identity-bootstrapping 六轨已走完仍无身份（v5.9.0：不主动询问用户，有则用无则默认无）且 ROE 禁自建账号。
> **进入路由（v6.5.0 S5-③）**：由 session-state-chain 决策树「仍无身份」分支与 identity-bootstrapping
> 全轨失败移交链进入——认证后项必须先过本轨四通道评估，才允许移交（与 s5.md S5-2a 必做前置同源）。
> 原则：认证后项**禁止直接 premise_failed 全量移交**——先逐项过本轨四通道评估，能拿到存在性证明的按三态登记，确实不可观测的才移交（移交原因必须写明「降级轨四通道逐项不可行」及原因）。

## 一、四条替代观测通道

| 通道 | 方法 | 可证明的结论 |
|---|---|---|
| ① 时延侧信道 | 同窗口基线 vs 载荷请求的耗时差分（≥3 样本，噪声收敛判据：差值稳定且远超基线抖动） | 盲注载荷到达业务层/真实处理发生（如推理/查询耗时跃升）——资源消耗与注入到达性证明 |
| ② 缓存行为差分 | 缓存键探测（无键参数/自定义头变体）+ 命中态对比（字节数/ETag/年龄头） | 参数是否到达键控逻辑、响应是否被缓存面污染 |
| ③ 错误文案差分 | 参数存在性/取值边界探针（空值/类型错/超长/特殊字符） | 端点存在性、参数校验位置（网关层 vs 业务层）、后端栈指纹 |
| ④ 自建数据回流 | 客户批准的写端点（若 ROE/客户追加批准）：唯一标记创建 → 清单/查询复核 → 读回全文 | 写链是否闭环、匿名写风险是否成立（存在性证明口径，唯一标记登记进《需人工清理清单》） |

## 二、执行纪律

1. 每通道探针**必须与同窗口基线成对**（无基线不判差——环境抖动会制造假阳性/假阴性）；
2. 时延类结论需 ≥3 样本且噪声收敛（参考 sqli-deep 时延三重测判据），单次不收敛如实标 needs_follow_up；
3. 通道④仅限客户/ROE 明确批准的端点，未批准一律跳过并留痕；
4. 结论一律三态登记（vulnerable / no_issue_found / needs_follow_up）+ update_coverage 引用原 checklist/计划项编号；
5. 与 session-state-chain 的关系：本轨是**无身份降级**，有身份时一律走 session-state-chain 带态测试，两者不可互相替代。

## 三、移交口径（S8 盲区章素材）

移交条目按固定四元组：条目名 / 前置依赖（何种登录态）/ 移交原因（降级轨四通道为何不可行）/ 恢复条件（客户提供账号后按 session-state-chain 复测）。
