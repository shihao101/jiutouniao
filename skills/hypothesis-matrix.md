# K3 假设模式库 · v4.8 威胁建模筛查矩阵（27 类 × 三态判定）

> **定位**：s3 威胁建模的系统性筛查规则库。STRIDE 逐元素枚举解决"组件全覆盖"，本矩阵解决"高风险假设系统性触发"——13 类高频漏触发缺口（SSRF 双语义/凭据面复用/数据类/直连绕过等）扩展为 27 类筛查问句。
> **口径**：27 类是**筛查问句而非强制假设**。每类输出三态判定之一，无对应攻击面的目标输出"不适用"记录——**不编造假设**（机制上杜绝诱导式幻觉）。
> **成本口径**：判定基于 S1/S2 既有证据推理，**零新增主动流量**；实测裁决在 s4 进行（R6 回填收敛）。
> **知识资产挂接**：行业优先级升格与数据类具象见 load_skill industry-templates（K1）；框架指纹先验见 load_skill framework-priors（K2）。

## 一、三态判定协议（每类必落其一，附证据指针）

| 三态 | 判定条件 | 留痕要求 |
|---|---|---|
| `假设` | 目标存在对应攻击面（结构/框架/参数位/功能特征命中触发条件） | 附证据指针（evidence/ 文件或 S2 资产/端点引用） |
| `不适用` | 目标经核查**无**对应攻击面 | 附证据（如"全部 14 路由逐一核查无取件参数位"）——核查过程留痕，不许空口判定 |
| `待判定` | 触发面存在但语义未知 | **双假设并列**（如类 12：穿越 OR SSRF），标注裁决手段，s4 实测后收敛 |

**反幻觉纪律**：宁可"待判定"不许编造；"不适用"必须有核查证据；"假设"必须指向具体面（组件×位置）。

## 二、筛查矩阵（27 类，触发条件全部为结构性/框架性，与具体目标无关）

| # | 筛查问句（触发条件） | 高风险假设模式 | 通用判据/裁决手段 |
|---|---|---|---|
| C-01 | 每个登录面（含后台/员工/患者/管理员各面独立核查） | 凭据三件套：用户枚举/锁定预言机/弱口令 | 各面独立探针：错误文案差分（枚举）、连续失败计数响应差（锁定预言机）、默认口令字典（弱口令）；预言机探针标准化见 identity-bootstrapping |
| C-02 | 验证码/滑块组件 | 签发端点匿名可达+答案前端泄露/重放/跳过/绑定关系 | 抓签发请求→匿名重放；JS/DOM 里找答案明文或可计算量；跳过校验直接提交；同码多次绑定测试 |
| C-03 | 重置与恢复功能 | token 可预测/步骤可跳/OTP 轰炸与枚举 | token 熵与时间戳关联性；直接跳后续步骤请求；同手机号高频触发响应差 |
| C-04 | 第三方登录（OAuth/CAS/扫码/证书） | 回调劫持/state 缺失/code 重放/service 未校验/账号预绑定接管 | 回调白名单枚举（loose redirect）；去 state 重放全流程；code 二次换票；绑定接口直连测试 |
| C-05 | 会话机制 | 固定/可预测/注销不完全/并发会话/cookie 属性 | 登录前后 token 差；采样熵与自增判定；注销后旧 token 复访；双会话并发策略 |
| C-06 | 自助注册 | 开放性/默认角色/批量注册/字段注入进后端 | 注册响应角色字段；批量注册限速观察；字段值带 payload 看落库回显（二阶面） |

| C-09 | 多租户框架特征（租户头/子域/组织切换） | 租户头/cookie 切换跨组织隔离 | 改租户标识重放；跨租户对象 ID 交叉访问；组织切换接口直连 |
| C-10 | 网关白名单/CDN/反代特征 | 边界绕过矩阵（规范化/Host/编码/方法/走私） | gateway-filter-playbook 矩阵逐格：路径规范化、Host 头、双重编码、异常方法、请求走私 |

## 三、《筛查矩阵判定表》产出规范（s3 交付物，M2 门机械校验）

- 文件路径固定：`deliverables/s3-筛查矩阵判定表.md`
- **27 行逐类三态留痕**，行格式（表格，引擎按行解析）：

```
| C-01 | <类名/触发面摘要> | 假设 | 证据：evidence/s2-loginpages.txt（3 个登录面） | TH-03/TH-04 |
| C-12 | /file/download 预览参数 | 待判定 | 证据：evidence/s2-endpoints.txt L18 | 双假设并列：穿越 OR SSRF，s4 裁决 |
| C-24 | 无邮件功能面 | 不适用 | 证据：全部 41 路由核查无发信入口；MX 无自管域 | — |
```

- 第 1 列固定 `C-<两位编号>`（C-01..C-27）；第 3 列三态判定格取值**必须恰为** `假设` / `不适用` / `待判定` 之一；第 4 列证据指针（evidence/ 文件、S2 资产/端点引用或核查过程描述）；第 5 列关联 TH 编号或双假设标注（可空）。
- "待判定"行必须在备注列写明**裁决手段**（s4 哪个动作裁决）。
- 判定依据 = S1/S2 既有证据 + load_skill framework-priors（K2）先验；**零新增主动流量**。

## 四、与威胁清单/回填的衔接（R6）

1. s3-2 威胁清单条目统一编号 `TH-01..TH-nn`；判定表第 5 列挂接对应 TH。
2. s4 实测新事实回填三态关系：`extends TH-xx`（挂原条目实测进展）/ `replaces TH-xx`（实测推翻，原条目 deprecated 留痕）/ `creates`（全新面，新编号）。
3. 待判定类在 s4 裁决后：判定表行同步收敛（追加裁决行注记，保留原待判定行留痕），威胁清单同步 extends/replaces。

## 五、R7 第一层自审清单（s3 收口前逐项核对，留痕入交付物）

①筛查矩阵 27 类三态完整性（判定表 27 行齐、每行有判定与证据）

## 六、风险排序补充（承接 s3-4）

矩阵判定出的"假设"按影响×可达性排序并入 s3-4 优先级队列；`待判定` 双假设并列项排期靠前（语义裁决是高风险假设收敛的最便宜路径）；行业模板升格项（K1）优先级只升不降。
