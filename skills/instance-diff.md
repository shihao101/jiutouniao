# 同构实例/节点行为差分（同指纹 ≠ 同行为——差异即边界信号）

> 适用信号：同一应用指纹出现在多端口/多节点/多源（灰度发布、双活集群、同构靶场换实例、CDN 多出口）。
> 原则：全部只读、跨实例采样限速串行；差异本身不是漏洞，**差异指示的配置漂移/版本滞后/门控不一致才是**。

## 阶段边界（S2，v6.2.0——与 heads/s2.md S2-10 同源）

S2 侦察窗口**只做同构信号的面识别与线索登记，不执行差分矩阵采样**：多端口/多节点/灰度信号识别自 S2 既有指纹与响应头（被动读取），命中即 `record_vt`（Priority=1，title 含「instance-diff」）并 `upsert_fact key=arch.signal`；第一节同构判定与第二节差分矩阵的主动 GET 采样自 S4 起投递执行（S2 发包采样属阶段越界）。

## 一、同构性判定（先确证再差分）

1. 指纹四件套对齐：Server 头/框架版本/网关节点标识（如 X-Proxy-Node 类自定义头）/静态资源 ETag。
2. 共享态验证：同一配置端点（如调试/环境信息类端点）跨实例取值比对——**同值=共享密钥/凭据库，S4/S5 情报可跨实例复用**；异值=实例独立，逐实例重测。
3. 结论落盘《实例同构性判定》节（交付物内），标注置信度与证据文件。

## 二、行为差分矩阵（同一探针集，跨实例对齐采样）

| 差分维度 | 探针方法 | 差异判读 |
|---|---|---|
| 状态码差分 | 同一端点清单逐实例 GET 对齐采样 | 200 vs 500/403 → 门控/数据面不一致 |
| 响应头差分 | 关键端点 -D 对齐 | 缓存命中态/安全头/节点标识差异 → 缓存与网关策略漂移 |
| body 字节/结构差分 | 首页与代表端点字节计数+JSON 结构键集合 | 大幅差异 → 版本滞后实例（旧版本=已知 CVE 面重测） |
| 行为语义差分 | 同参数请求（含边界值）跨实例 | 一实例 500 一实例 200 → 异常处理路径不一致（漏洞信号） |
| 密钥/配置值差分 | 调试类端点取值对齐 | 同值共享泄露面扩大；异值=逐实例接管链重估 |

## 三、产出与登记

- 交付物：《实例差分矩阵》表（动作×实例×结果×证据文件）；
- 每条差异三态裁决（vulnerable / no_issue_found / needs_follow_up）+ record_finding / update_coverage 引用；
- 命中实例特有漏洞时，注明「仅 <实例标识> 可达」——影响评估按可达实例面收窄表述。

## 四、纪律

- 采样限速串行，禁止并发打多实例；跨实例凭据/票据复用只做存在性证明；
- 差分探针与基线探针成对登记，禁止无基线判差异（防环境抖动误判，参考健康窗口纪律）。
